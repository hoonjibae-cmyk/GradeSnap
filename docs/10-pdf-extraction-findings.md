# 10. PDF 자동 추출 실험 결과

**실험일**: 2026-08-05
**대상**: 시험지 + 정답지 4세트 (실제 운영 파일)
**도구**: [`tools/pdf_probe.py`](../tools/pdf_probe.py) — 이 실험을 위해 작성한 진단 프로토타입

[04 §2.5](04-data-model.md)에서 "③ 매회 신규 등록을 5분 이내로"를 최상위 과제로 잡았고,
그 해법으로 **문항 번호 OCR + 답안 영역 자동 검출 + 정답지 붙여넣기**를 제안했습니다.
실제 파일로 검증한 결과입니다.

|---|---|---|---|---|

## 2. PDF가 네 가지 성격으로 나뉩니다

같은 학원의 시험지인데 PDF 내부 구조가 전부 다릅니다.
**이걸 먼저 판별하지 않으면 엉뚱한 처리를 하게 됩니다.**

| 성격 | 판별 | 원인(추정) | 처리 |
|---|---|---|---|
| **text** | 텍스트 추출 정상 | 워드/구글독스 → PDF | ✅ 텍스트 레이어에서 직접 추출 |
| **outlined** | 텍스트 없음, 벡터 경로 다수 | 한글(HWP) → PDF, 글꼴 아웃라인화 | 렌더 후 OCR |
| **mojibake** | 추출은 되나 `!`, `#` 등 쓰레기 | 브라우저 인쇄, 폰트 서브셋에 ToUnicode 누락 | 렌더 후 OCR |
| **scanned** | 이미지뿐 | 종이 스캔 | 렌더 후 OCR |

`mojibake`는 특히 함정입니다. **텍스트 길이만 보면 정상으로 보이지만 내용이 깨져 있습니다.**
실제로 유니크보카 PDF가 이 경우였습니다.

```
유니크보카 추출 결과:  '!'  '#'  ',--./+00,1123456789:;<&=4-,>5&410?>24@>78A1968B7/-0'
```

→ 도구에 **가독 문자 비율 45% 미만이면 mojibake로 판정**하는 검사를 넣었습니다.

> 🟢 이 발견은 [09](09-yunique-voca-integration.md)의 판단을 확증합니다.
> 유니크보카는 **PDF를 경유하면 안 되고 DOM에서 직접 좌표를 뽑아야** 합니다.
> 브라우저 인쇄 PDF는 텍스트가 살아남지 않습니다.

## 3. 답안 영역이 두 방식으로 그려집니다

| 방식 | 예 | 검출법 |
|---|---|---|
| **언더스코어 문자** | `① 해석: ____________` | `get_text("words")`에서 `_{3,}` 검색 |
| **실제 선(벡터)** | 단어시험의 밑줄 | `get_drawings()`에서 납작한 사각형 추출 |

둘 다 좌표를 정확히 얻을 수 있습니다. 언더스코어 쪽이 더 깔끔합니다
(선은 표 테두리와 섞이기 때문).

### 오검출은 매칭 단계에서 자연히 걸러집니다

논리반 시험지에서 답안란 후보 110개가 검출됐지만, 그중 70개는 지문 박스·표 테두리였습니다.
**그런데 이건 문제가 되지 않습니다.** 문항 번호와 매칭되지 않는 후보는 자동으로 탈락하기 때문입니다.

그래서 의미 있는 지표는 "검출 정확도"가 아니라 **문항 커버리지**입니다.

```
인쇄된 문항 20개 중 17개에 답안 영역이 붙음  → 커버리지 85%
못 찾은 것: 1번, 5번, 20번  → 이 3개만 수동 지정
```

**선생님에게 전부 확인시키지 않고 못 찾은 것만 보여주는 것** — 이게 5분과 30분을 가릅니다.

## 4. 정답지가 세 가지 형식입니다

앞서 "번호별 나열형"으로만 알고 있었는데, 실제로는 셋 다 존재합니다.

### 형식 1 — 병렬형 (M9 단어시험) 🟢 가장 좋음
시험지와 **완전히 같은 배열**에 정답 열만 추가된 형태입니다.

```
시험지                     정답지
1.  traffic  ________      1.  traffic  (왕래하는) 차량, 교통(량)
2.  rush     ________      2.  rush     서두르다; 돌진하다; 분주함; 돌진
```

번호·제시어·정답이 한 줄로 묶여 있어 **파싱이 거의 무손실**입니다.
실험에서 **90개 전부 추출**했습니다.

### 형식 2 — 밑줄 표시형 (어휘끝 수능)
시험지와 레이아웃이 같고, **정답 선택지에 밑줄만 그어진** 형태입니다.

```
③ 비관주의, 비관론 (↔ optimism)     ← 밑줄 = 정답
```

레이아웃이 같으므로 원리상 차분이 가능하지만, 이 파일은 벡터 아웃라인이라
**밑줄 위치를 OCR 없이 읽을 수 없습니다.** 다만 밑줄은 벡터로 남아 있어
`get_drawings()`로 위치를 잡고, 그 위치의 선택지 번호만 OCR하면 됩니다.

> ⚠️ 정답지가 6페이지, 시험지가 4페이지로 **페이지 수가 다릅니다.**
> 정답 밑줄 때문에 줄바꿈이 달라진 것으로 보입니다.
> **페이지 단위 픽셀 차분은 쓸 수 없고, 문항 단위로 매칭해야 합니다.**

### 형식 3 — 해설지형 (논리반 클리닉)
정답 + 해석 + 오답 이유까지 담긴 완전한 문서입니다.

```
1. 정답: ②
☐ ① Countershading: How Light and Shadow Can Betray an Animal's Shape
   (해석) 위장술: 빛과 그림자가 어떻게 동물의 형태를 드러낼 수 있는가
   → ... (오답: 지엽적 사실 확대/왜곡)
```

`(\d+)\s*[.)]?\s*정답\s*[:：]\s*(.+)` 패턴으로 추출됩니다. 실험에서 15개 추출.

**부가 가치**: 해설지에는 **오답 이유와 인정 답안 정보**가 들어 있습니다.
```
"써도 정답 인정" / "expand → expanded (수동형)" / "2. 문항 B 모범답안 — [분사구문]"
```
이걸 파싱하면 `accepted`(인정 답안)와 `rubric`(채점 기준)을 자동으로 채울 수 있습니다.
장기적으로 매우 유용합니다.

## 5. 🔴 문항 번호가 Part마다 리셋됩니다

논리반 시험지의 실제 구조입니다.

```
Part 1. 지난 수업 지문 클리닉    →  1, 2, 3, 4, 5, 6
Part 2. 어법 판단 및 교정        →  1, 2, 3, ... 8      ← 1번이 또 나옴
Part 3. 혼동하기 쉬운 어휘       →  1, 2, 3, 4          ← 또 나옴
```

정답지에서 뽑은 결과도 `1번 → ②`, `1번 → comprehensible`처럼 **1번이 중복**됩니다.

**대응**: `question.number`를 정수가 아니라 **문자열**로 두고,
`Part`/`지문` 등 섹션 헤딩을 함께 파싱해 `"P2-1"` 같은 복합 키를 만듭니다.
[04 데이터 모델](04-data-model.md)의 `question.number`는 이미 문자열이므로 스키마 변경은 없습니다.
파서와 매칭 로직만 섹션을 인식하면 됩니다.

## 7. 확정된 등록 파이프라인

```
시험지 PDF 업로드
   ↓
PDF 성격 판별 (text / outlined / mojibake / scanned)
   ↓
┌─ text ────────────────────────────┐   ┌─ 그 외 ──────────────┐
│ 텍스트 레이어에서 직접 추출        │   │ 300dpi 렌더 후 OCR   │
│  · 문항 번호 + 좌표               │   │  · 문항 번호 OCR     │
│  · 언더스코어/벡터선 → 답안 영역   │   │  · 선/셀 검출        │
└───────────────────────────────────┘   └──────────────────────┘
   ↓
정답지 업로드 → 형식 자동 판별(병렬/밑줄/해설) → 번호별 정답 추출
   ↓
정답 개수 ↔ 문항 커버리지 대조
   ↓
못 찾은 문항만 화면에 표시 → 선생님이 드래그로 보정
   ↓
저장
```

## 9. 문법 백지 TEST 세트 조사 (Drive)

[04 §2.5](04-data-model.md)의 **② 고정 세트** 분류에 해당합니다.
전체 세트를 Drive에서 확인했습니다.

### 규모

```
문법백지TEST/
├── Level1/pdf/     시험지 16 · 정답지 15 · 형광펜 표시한 정답지 15
├── Level2/pdf/     시험지 14 · 정답지 · 형광펜 표시한 정답지
├── Level3/pdf/     시험지 14 · 정답지 · 형광펜 표시한 정답지
└── Level high/pdf/ 시험지 15 · 정답지 · 형광펜 표시한 정답지
```

**총 59개 유닛** (레벨 4종 × 챕터 14~16개), 유닛당 1~3페이지.
챕터 구성은 레벨마다 다릅니다 (Level1은 인칭대명사~다양한 문장의 종류,
Level high는 문장의 형식~형용사와 부사).

### 🟢 시험지와 정답지의 텍스트가 완전히 같고, 정답만 차이납니다

`Level1 / Chapter 4. 조동사`로 확인한 결과입니다.

```
시험지        …  2) 강한 추측 (~임에 틀림 없다)
                 부정 :         (~일 리가 없다)      ← 빈칸

정답지        …  부정 : can't  (~일 리가 없다)       ← 정답
형광펜 정답지  …  부정 : can't  (~일 리가 없다)       ← 동일 + 형광 배경
```

나머지 본문은 **한 글자도 다르지 않습니다.**

이건 등록 관점에서 최상의 조건입니다.

| 얻는 것 | 방법 |
|---|---|
| **정답 텍스트** | 시험지 ↔ 정답지 **텍스트 차분** → 추가된 토큰이 곧 정답 |
| **답안 영역 좌표** | 차분된 토큰의 정답지 내 위치 = 학생이 쓸 자리 |
| **검증** | 형광펜 정답지의 **배경색 영역**으로 교차 확인 |

[04 §2.5](04-data-model.md)에서 폐기했던 "차분으로 좌표와 정답을 동시에 추출" 방식이
**이 세트에서는 그대로 성립합니다.** 레이아웃이 동일하기 때문입니다.
(폐기한 이유였던 "정답지가 번호별 나열형"은 ③ 분류에만 해당하는 얘기였습니다.)

### 텍스트 레이어

정상입니다. 한글이 그대로 추출됩니다 → **OCR 불필요.**

### 예상 등록 작업량

| 조건 | 유닛당 | 전체(59유닛) |
|---|---|---|
| 차분 자동 추출이 잘 될 때 | 2~3분 | **2~3시간** |
| 수동 보정이 절반쯤 필요할 때 | 5~8분 | 5~8시간 |
| 자동화 없이 전부 수동 | 20분+ | 20시간+ |

**일회성 비용**입니다. 한 번 등록하면 이후 운영 비용이 0이고,
선생님은 필요한 유닛을 골라 출력·촬영만 하면 됩니다.

### ⚠️ 정리가 필요한 것

- **Level1 시험지에 중복 파일**: `ch12.전치사.pdf`와 `ch.12 전치사.pdf`가
  파일 크기까지 동일(210,327B)합니다. 등록 전에 정리해야 합니다.
- **파일명 규칙 불일치**: `ch4.조동사` / `Ch4. 조동사` / `Ch 4. 수동태 시험지` 등
  레벨마다 표기가 다릅니다. 시험지↔정답지 자동 짝짓기를 하려면 정규화가 필요합니다.
  (`[Cc]h\s*\.?\s*(\d+)` 로 챕터 번호를 뽑아 매칭하면 대부분 해결됩니다.)

### 아직 확인 못 한 것

Drive 파일은 **네트워크 정책상 이 세션에서 직접 내려받을 수 없어**
(`drive.google.com` CONNECT 403) `pdf_probe.py`를 돌리지 못했습니다.
텍스트 내용은 MCP로 읽었지만 **좌표는 확인하지 못했습니다.**

→ 대표 파일 3~4개(시험지+정답지 쌍)를 채팅에 직접 올려주시면
   좌표 추출까지 검증하고 작업량을 확정할 수 있습니다.
