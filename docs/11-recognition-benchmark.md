# 11. 인식 벤치마크 실행 절차

> 🛑 **이 벤치마크는 [12 §12.8](12-page-level-grading.md#128-새-벤치마크--새-샘플이-필요-없습니다)로
> 대체되었습니다 (2026-08-07).**
>
> 여기 적힌 절차는 **템플릿 좌표로 칸을 잘라** 하나씩 읽히는 방식을 전제합니다.
> 페이지 단위 채점으로 전환하면서 crop 자체가 없어졌습니다.
> 새 벤치마크가 재는 것은 '인식 정확도'가 아니라 **'선생님 채점과의 일치율'**입니다.
>
> 아래 내용 중 **11.1의 지표 정의(오인식·관대·엄격 오류)와 11.4의 결과 해석**은
> 그대로 유효해 12에서 재사용합니다.

Phase 0의 관문입니다. **이 결과로 Phase 1 착수 여부가 결정됩니다.**
([07 §0.2](07-roadmap.md), [07 §0.5](07-roadmap.md))

> **판단 기준** — 영단어 인식 정확도 **95% 이상** & 오인식률 **1% 미만** → Phase 1 착수

도구는 준비되어 있습니다. **지금 없는 것은 데이터뿐입니다.**

## 11.1 무엇을 재는가

측정 대상은 인식기가 아니라 **"정답을 알려주는 것이 도움이 되는가"** 입니다.

| 방식 | 무엇을 알려주고 읽히는가 | 의미 |
|---|---|---|
| `blind` | 아무것도 | 기준선. 이것보다 나아지지 않으면 정답을 알려줄 이유가 없다 |
| `prefix` | 인쇄된 첫 글자만 | 로드맵 0.2의 1순위. 정보량이 가장 적고 관대함 위험도 가장 낮다 |
| `candidates` | 이 칸의 정답 | 실서비스 방식. 정확도는 가장 높겠지만 **관대함이 여기서 터진다** |
| `pool` | 시험지 전체 정답 목록 | 어느 칸의 답인지는 안 알려준다. 어휘만 제한하는 절충안 |

### 지표 다섯 가지

| 지표 | 정의 | 왜 보는가 |
|---|---|---|
| 정확도 | 인식 결과 == 학생이 실제로 쓴 글자 | 기본 성능 |
| 판독불가율 | 인식기가 스스로 "못 읽겠다"고 한 비율 | 검수 대기열의 크기 |
| **오인식률** | 읽었다고 하면서 **다르게** 읽은 비율 | **치명적.** 판독불가는 사람에게 넘어가지만 오인식은 그대로 확정된다 |
| 관대오류 | 학생이 틀렸는데 맞다고 채점되는 비율 | 선생님이 시스템을 못 믿게 되는 지점 |
| 엄격오류 | 학생이 맞았는데 틀렸다고 채점되는 비율 | 학부모 항의로 돌아온다 |

**필체 등급별로 나눠 봅니다. 전체 평균은 의미가 없습니다.**
악필 20%가 전부 틀려도 전체 평균은 96%로 나옵니다. 그 96%로 Phase 1에 들어가면
현장에서 악필 학생만 계속 오채점되고, 그게 이 시스템이 죽는 방식입니다.

## 11.2 답안지 수집 (0.1)

30장 이상. 조건은 로드맵 0.1과 같고, 지키지 않으면 측정값이 실사용과 무관해집니다.

- **채점 전 상태로 촬영** — 빨간펜이 답안을 덮으면 인식이 아니라 빨간펜을 재게 됩니다
- **책상에 평평하게** — 손에 들면 종이가 휘고, 휨은 정합 실험(0.3)에서 따로 잽니다
- **악필을 전체의 20% 이상** 포함 — 잘 쓴 답안만 모으면 통과 기준만 통과하고 현장에서 실패합니다
- 지운 자국 / 칸을 벗어난 글씨 / 무응답 포함
- 휴대폰 촬영본 (스캐너 아님)
- **선생님의 채점 결과(오답 번호)** — 이것이 라벨의 원천입니다

> ⚠️ **먼저 확인할 것**: 선생님마다 채점 표기가 다릅니다([08](08-sample-analysis.md)).
> 동그라미가 정답 표시인지 오답 표시인지 **선생님별로 확인**하십시오.
> 이걸 뒤집어 알면 벤치마크 결과 전체가 뒤집힙니다. ([07 §0.1](07-roadmap.md))

## 11.3 실행

### 1단계 — crop 만들기

```bash
python3 tools/make_crops.py \
    --template templates/BJ-L2-CH08.json \
    --image samples/BJ-L2-CH08_홍길동_p1.jpg \
    --page 1 --student 홍길동 \
    --out crops/ --manifest manifest.csv
```

학생마다 반복하면 `manifest.csv`에 쌓입니다.
`answer`·`candidates` 열은 템플릿에서 자동으로 채워지므로 정답표를 다시 입력하지 않습니다.

> 정합(마커 기반 homography)은 아직 구현 전입니다. Phase 0 벤치마크는
> **정면으로 반듯하게 찍은 사진**을 전제로 템플릿 좌표를 그대로 씁니다.
> 정합 자체의 오차는 0.3에서 따로 잽니다 — 두 실험을 섞으면 원인을 못 가립니다.

### 2단계 — 라벨 채우기 ← 여기가 진짜 비용

30장 × 50문항 = 1,500칸을 손으로 옮겨 적으면 이 벤치마크는 돌아가지 않습니다.
두 가지를 이용해 타이핑을 10분의 1로 줄입니다.

1. **선생님이 이미 오답 번호를 적어 두었습니다.** 오답이 아닌 칸은 정답을 쓴 것이므로
   `truth = 정답`으로 자동으로 채웁니다. **타이핑은 오답 칸만** 하면 됩니다.
2. **필체 등급은 학생의 성질이지 문항의 성질이 아닙니다.** 답안지 한 장을 보고
   한 번 매기면 그 학생의 모든 행에 적용됩니다.

```bash
# 홍길동: 필체 보통, 오답 3·7·12~14·30번, 무응답 41·42번
python3 tools/fill_truth.py --manifest manifest.csv \
    --student 홍길동 --grade fair --wrong 3,7,12-14,30 --blank 41,42

# 손으로 채울 칸만 뽑아 보기
python3 tools/fill_truth.py --manifest manifest.csv --todo
```

남은 오답 칸의 `truth`에는 **학생이 실제로 쓴 글자**를 적습니다.
정답이 아니라 `hesitage`처럼 **틀리게 쓴 그대로**입니다. 이게 관대함 측정의 재료입니다.

> 자동으로 채운 라벨은 `truth_source=assumed`로 표시됩니다.
> 선생님이 정답표에 없는 표기를 정답 처리했을 수 있어 100% 신뢰는 못 합니다.
> 그래서 `bench_ocr.py`가 **인식 결과와 어긋난 assumed 행만** 따로 세어 줍니다.
> 그 몇 건만 실물과 대조하면 됩니다. 전수 검사는 필요 없습니다.

### 3단계 — 돌리기

```bash
export ANTHROPIC_API_KEY=...

# 소규모 예행 — 20건만
python3 tools/bench_ocr.py --manifest manifest.csv --limit 20 --modes blind,candidates

# 본 실행
python3 tools/bench_ocr.py --manifest manifest.csv --modes blind,prefix,candidates,pool

# 대량이면 Batch API — 비용 50%, 대신 응답시간은 못 잽니다
python3 tools/bench_ocr.py --manifest manifest.csv --batch
```

응답시간은 동기 실행에서만 나옵니다. **비용은 배치로, 응답시간은 동기 소량으로**
나눠 재는 것이 효율적입니다.

## 11.4 결과 읽는 법

`candidates`가 `blind`보다 정확도가 높은 것은 당연합니다. 볼 것은 그게 아닙니다.

1. **관대함 테스트 표를 먼저 봅니다.** 학생이 틀리게 쓴 답안 중 인식기가 정답으로
   읽어버린 비율입니다. `candidates`에서 이 값이 크게 튀면 **실서비스 방식을
   그대로 쓸 수 없습니다.** `prefix`나 `pool`로 정보량을 낮춰야 합니다.
2. **악필(poor) 행만 봅니다.** 여기가 실제 검수 부하를 결정합니다.
3. **오인식률과 판독불가율을 구분합니다.** 판독불가는 비용(검수 시간)이고
   오인식은 손해(오채점)입니다. 오인식 1건이 판독불가 20건보다 나쁩니다.

### 결과에 따른 판단

| 결과 | 해석 | 다음 |
|---|---|---|
| `candidates` 정확도 ≥95% & 오인식 <1% & 관대함 낮음 | 가설 성립 | Phase 1 착수 |
| 정확도는 높은데 관대함이 큼 | 인식이 아니라 **암기**를 하고 있음 | `prefix`/`pool`로 낮춰 재측정 |
| 악필만 크게 나쁨 | 전체 평균은 무의미 | 악필을 검수로 라우팅하는 임계값 설계 |
| `blind`와 차이 없음 | 정답을 알려줄 이유가 없음 | 설계 원칙 2를 폐기하고 단순화 |
| 전 방식 미달 | 이 문항 유형이 어려운 것 | 대상 문항군 축소([07 §0.6](07-roadmap.md)) 또는 중단 |

**마지막 줄이 실제 선택지라는 점이 중요합니다.** Phase 0은 통과시키려고 하는
실험이 아니라 **중단해도 되는지 확인하는** 실험입니다.

## 11.5 현재 상태

| 항목 | 상태 |
|---|---|
| crop 생성기 (`make_crops.py`) | ✅ |
| 라벨 채우기 (`fill_truth.py`) | ✅ |
| 벤치마크 harness (`bench_ocr.py`) | ✅ (가짜 응답으로 전 경로 검증 완료) |
| 시험지 템플릿 | ✅ 문법 백지 TEST 58유닛 ([10 §10.6](10-pdf-extraction-findings.md)) |
| 채점 전 촬영 답안지 | 🟡 2차 수집분 약 50장이 조건에 맞음([08](08-sample-analysis.md)) — **재업로드 필요** |
| 그 답안지에 대응하는 템플릿 | ❌ 대부분 유니크보카·워드마스터 계열 |
| **선생님 채점 결과 (= 정답 라벨)** | ❌ **막힌 지점** |
| 선생님별 채점 표기 규칙 | ❌ 미확인 |
| 상용 OCR 비교군 | ⏸ VLM 결과를 먼저 보고 필요하면 추가 |

2차로 수집된 약 50장은 **채점 전·평평·정면**으로 조건을 이미 만족합니다.
촬영 지시가 제대로 전달된 결과입니다. 남은 것은 두 가지입니다.

1. **정답 라벨** — 각 답안지의 오답 번호. 선생님이 채점을 마쳤다면 이미 존재합니다.
   `fill_truth.py`가 이것만 있으면 나머지를 자동으로 채웁니다.
2. **답안지에 맞는 템플릿** — 좌표가 있어야 crop이 나옵니다.
   가장 빠른 길은 **문법 백지 TEST 답안지를 새로 걷는 것**입니다.
   58유닛 템플릿이 이미 등록되어 있어 crop이 바로 나옵니다.
   유니크보카 계열은 생성기 연동([09](09-yunique-voca-integration.md))이 먼저입니다.

**둘 다 갖춰지면 라벨링 반나절, 실행 30분입니다.**
