# 05. 채점 엔진 설계

> ⚠️ **이 문서의 일부는 [12. 페이지 단위 채점](12-page-level-grading.md)으로 대체되었습니다 (2026-08-07).**
>
> 인식 입력이 '칸 하나의 crop'에서 '페이지 전체'로 바뀌었습니다(§3.1).
> **정규화·매칭·확신도 라우팅·검수 화면(§3.2·§3.3·§6·§7)은 그대로 유효하며,
> 오히려 더 중요해집니다** — AI가 전사를 맡는 만큼 정오 판정은 규칙이 쥐고 있어야 합니다.

## 0. 대원칙

> **틀리게 자동 확정하느니, 사람에게 넘긴다.**

오채점 1건이 주는 신뢰도 손실은 검수 100건이 주는 피로보다 큽니다.
선생님이 "혹시 몰라서" 전부 다시 확인하기 시작하면 이 시스템은 존재 이유를 잃습니다.
그래서 모든 채점기는 **판정과 함께 확신도를 반환**하며, 확신이 없으면 판정하지 않습니다.

## 1. 채점기 구성

문항 유형에 따라 채점기가 선택됩니다.

| 채점기 | 대상 | 외부 API | 속도 |
|---|---|---|---|
| `MarkGrader` | 선택형 마킹 | 없음 | 즉시 |
| `DictGrader` | 단답 (단어·뜻) | 인식 API | 빠름 |
| `SentenceGrader` | 문장 영작 | VLM | 보통 |
| `RubricGrader` | 조건부 서술형 | VLM | 느림 |

---

## 2. MarkGrader — 선택형 마킹

`유 / 반` 같은 선택 영역이 대상입니다. 외부 API 없이 로컬에서 처리합니다.

```
각 선택지 영역에 대해:
  1. 인쇄된 테두리 원/글자를 템플릿 기준 이미지와 차분(difference)
  2. 남은 픽셀의 잉크 비율 ink_ratio 계산
  3. 선택지 간 ink_ratio 비교
```

판정:

| 조건 | 결과 | 확신도 |
|---|---|---|
| 한 선택지만 임계 초과, 2위와 차이 큼 | 해당 선택지 | 높음 |
| 두 선택지 모두 임계 초과 | 중복 마킹 → 검수 | — |
| 모두 임계 미만 | 무응답 → 검수 | — |
| 1위·2위 차이가 작음 | 검수 | — |

**주의점**
- 학생이 동그라미를 크게 쳐서 옆 선택지를 침범하는 경우가 실제로 잦습니다.
  → 침범 감지 시 무조건 검수로 보냅니다.
- 지우고 다시 친 흔적(연필 자국)은 ink_ratio를 애매하게 만듭니다.
  → 1·2위 차이 임계로 걸러집니다.
- 임계값은 하드코딩하지 않고 **Phase 0 실측 데이터로 결정**합니다.

---

## 3. DictGrader — 단답 채점

A유형의 뜻, B유형 빈칸, E유형 서술형 2가 대상입니다.

### 3.0 인쇄 첫 글자(`prefix`) 처리

일부 시험지는 답안 칸에 **첫 글자를 인쇄해두고 나머지를 학생이 씁니다.**

```
28. 보호하다, 지키다; 경계, 경호원   g̲u̲a̲r̲d̲     ← 'g'는 활자, 'uard'는 손글씨
```

crop 안에 활자와 손글씨가 공존하므로 처리 규칙이 필요합니다.

```
1. prefix가 있으면 인식기에 함께 알려준다
   "이 칸의 첫 글자 'g'는 인쇄된 것이다. 학생이 이어서 쓴 글자를 읽어라."
2. 인식 결과가 prefix로 시작하면 그대로 사용
   시작하지 않으면 prefix + 인식결과로 조립
3. canonical과 비교
```

**이 케이스는 오히려 정확도가 올라갑니다.** 첫 글자가 확정되면 후보 공간이 크게
줄고, 활자의 일정한 형태가 손글씨 시작점을 찾는 기준이 됩니다.
`prefix` 제공 유무에 따른 정확도 차이는 Phase 0에서 실측합니다.

### 3.1 인식
crop 이미지를 인식기에 넘기되, **정답 후보를 함께 전달**합니다.

```
입력: crop 이미지
      + 정답: "응답하다"
      + 인정 답안: ["대답하다", "반응하다", "응하다"]
      + 지시: 학생이 쓴 글자를 그대로 옮겨 적어라.
              후보에 맞추려고 억지로 해석하지 마라.
              읽을 수 없으면 판독불가로 답하라.
```

> 후보를 알려주는 것은 인식률을 크게 올리지만, **오답을 정답으로 읽어버릴 위험**이
> 동시에 커집니다. 그래서 "그대로 옮겨 적어라"를 명시하고, 판정은 별도 단계에서 합니다.
> 인식과 채점을 분리하는 이유가 이것입니다.

### 3.2 정규화
```
공백 제거 · 유니코드 정규화(NFC) · 전각→반각
대소문자 통일 (영단어, ignore_case일 때)
괄호 보충 설명 제거: "응답하다(대답)" → "응답하다"
구분자 분리: "응답하다/대답하다" → ["응답하다", "대답하다"]
```

### 3.3 매칭
```
1. 인정 답안과 완전 일치           → 정답 (확신도 = 인식 확신도)
2. 편집거리 ≤ allow_typo_distance  → 정답 (확신도 하향)
3. 한국어 뜻의 경우 유사도 판정     → 애매하면 검수
4. 명백히 다른 단어                → 오답
5. 인식 실패 / 무응답 판정 애매     → 검수
```

한국어 뜻 채점의 어려움: 학생이 `respond` 뜻으로 **"반응"** 이라고만 써도 맞다고
봐야 할 수 있습니다. 이런 경우는 자동으로 정답 처리하지 않고 **검수로 보낸 뒤,
선생님이 정답 처리하면 그 표현을 인정 답안에 자동 추가 제안**합니다.
사전이 사용하면서 스스로 좋아지는 구조입니다.

### 3.4 문항 단위 집계 (B유형)
`grading_unit = "question"`인 경우:

```
모든 빈칸 정답            → 문항 정답
하나라도 명백한 오답      → 문항 오답
하나라도 검수 필요        → 문항 전체 검수
```
검수 화면에는 빈칸 하나가 아니라 **문장 전체 crop**을 보여줍니다.

## 4. SentenceGrader — 문장 영작

C유형이 대상입니다. **인식과 채점을 한 번에** 수행합니다.
손글씨 문장을 텍스트로 옮기는 과정에서 이미 오류가 섞이므로,
텍스트만 놓고 채점하면 "OCR이 만든 오류"를 "학생의 오류"로 오판합니다.

입력:
- 손글씨 crop 이미지
- 정답 문장
- 문항의 rubric (오류 항목별 정답/오답/검수 정책)

출력 스키마:
```json
{
  "transcription": "This book is about King Sejong who invented Hangeul.",
  "legible": true,
  "verdict": "wrong",
  "errors": [
    { "type": "comma_missing", "detail": "Sejong 뒤 쉼표 누락", "span": "Sejong who" }
  ],
  "confidence": 0.86,
  "reason": "관계대명사 계속적 용법의 쉼표가 누락되었습니다."
}
```

판정 로직:
```
legible = false                        → 검수
errors 중 rubric이 'wrong'인 항목 존재  → 오답
errors 중 'review'인 항목 존재          → 검수
errors 없음 또는 전부 'correct'         → 정답
confidence < threshold                  → 판정 무시하고 검수
```

**AI가 판정하는 게 아니라 rubric이 판정합니다.** AI는 "어떤 오류가 있는지"만
찾고, 그 오류를 감점할지 말지는 선생님이 설정한 rubric이 결정합니다.
이 분리가 없으면 AI의 관대함을 통제할 수 없습니다.

### 관대함 방지
이 시험은 "문장을 정확히 암기했는가"를 봅니다. AI가 "의미는 통하니 맞다"고
판정하면 시험이 무의미해집니다. 대응:
- 프롬프트에 *"의미가 통하는지가 아니라 정답 문장과 일치하는지를 본다"* 명시
- **일부러 오답을 쓴 검증 세트**를 만들어 놓고 회귀 테스트로 관대함을 상시 측정
- 프롬프트나 모델을 바꾸면 이 세트를 다시 돌립니다

## 5. RubricGrader — 조건부 서술형

E유형 서술형 3처럼 조건이 복잡한 문항입니다.
**점수를 자동 확정하지 않습니다.** AI는 조건별 충족 여부만 체크합니다.

```json
{
  "transcription": "...",
  "checklist": [
    { "item": "제시어 12개 모두 사용", "status": "met" },
    { "item": "형태 변형 3개",        "status": "likely_met" },
    { "item": "동명사 주어 사용",     "status": "met" },
    { "item": "분사구문 사용",        "status": "unclear" },
    { "item": "문맥 적합성",          "status": "unclear" }
  ],
  "suggested_score": 3,
  "max_score": 5,
  "requires_teacher": true
}
```

검수 화면은 손글씨 원본 + 체크리스트 + 제안 점수를 나란히 보여주고,
선생님은 확인 후 점수를 확정합니다. 선생님의 작업이 "읽고 채점"에서
"확인하고 누르기"로 바뀌는 것만으로 충분한 이득입니다.

## 6. 확신도와 라우팅

확신도는 단계별 값의 곱으로 계산합니다.

```
confidence = page_quality × recognition_conf × match_conf
```

- `page_quality` — 흐림·기울기·마커 검출 상태
- `recognition_conf` — 인식기 반환값
- `match_conf` — 정답 매칭 강도 (완전일치 1.0, 오타허용 매칭 0.7 등)

**페이지 품질이 나쁘면 그 페이지의 모든 문항 확신도가 함께 내려갑니다.**
사진 한 장이 흐린데 문항 20개가 전부 자동 확정되는 상황을 막기 위함입니다.

```
confidence ≥ auto_confirm_threshold (기본 0.9)  → 자동 확정
그 미만                                          → 검수 큐
```

임계값은 템플릿별로 조정합니다. 새 양식은 높게(0.95) 시작해
데이터가 쌓이면 낮춥니다.

## 7. 검수 화면 요구사항

검수 화면의 속도가 곧 시스템의 가치입니다.
**1건당 3초** 안에 처리 가능해야 합니다.

- 잘라낸 답안 이미지를 크게, 정답을 바로 옆에
- AI 판단 근거를 한 줄로
- 키보드만으로 처리: `1` 정답 · `2` 오답 · `3` 부분점수 · `Space` 다음 · `←` 이전
- 원본 전체 이미지 토글 (`F`) — crop이 애매할 때
- 같은 문항 번호를 학생 전체에 걸쳐 연속 검수하는 **세로 모드**
  (같은 정답을 반복 판단하므로 학생 단위보다 훨씬 빠릅니다)

### 전 문항 검수 모드 (악필 대응)

실제 샘플에서 **5명 중 1명은 사람이 읽어도 판독이 어려운 수준**의 필체였습니다.
이런 학생은 문항 대부분이 검수로 넘어옵니다.

문항을 하나씩 crop으로 띄우는 것은 이 경우 오히려 느립니다.
**원본 답안지 전체를 크게 띄우고 수기 채점하듯 처리하는 모드**를 따로 둡니다.

```
전 문항 중 검수 비율 > 60%  → 자동으로 전 문항 검수 모드 제안
```

학생별 인식 실패율을 누적해, 반복적으로 실패하는 학생은 처음부터 이 모드로 보냅니다.
악필은 고쳐지지 않으므로, 매번 검수 큐를 거치게 하는 것은 낭비입니다.

## 8. 정확도 측정

측정 없이 개선은 불가능합니다. 다음을 상시 집계합니다.

| 지표 | 정의 | 목표 |
|---|---|---|
| **오채점률** | 자동 확정 중 교사가 뒤집은 비율 | **< 0.5%** |
| 검수율 (문항 기준) | 전체 문항 중 검수로 간 비율 | 30% → 20% |
| 검수율 (학생 기준) | 학생별 검수율의 분포 | 편차 큼 — 평균만 보지 말 것 |
| 인식 실패율 | 판독 불가 비율 | < 10% |
| 재촬영률 | 품질 미달로 재촬영한 비율 | < 10% |
| 처리 시간 | 업로드 → 결과 | < 15초/장 |

오채점률은 **교사가 자동 확정 결과를 뒤집었을 때** 측정됩니다.
따라서 검수 화면에서 자동 확정 항목도 언제든 수정 가능해야 하며,
그 수정이 곧 시스템의 성능 데이터가 됩니다.

정기적으로 무작위 표본 20장을 뽑아 전 문항 수기 대조하는 **감사(audit)** 를
Phase 1 기간 동안 매주 수행합니다.

> **평균 검수율만 보면 안 됩니다.** 필체 편차 때문에 "평균 20%"가
> 실제로는 "학생 80%는 5%, 학생 20%는 90%"일 수 있습니다.
> 학생 단위 분포를 함께 봐야 어디를 개선할지 판단할 수 있습니다.
