## 2. 주요 발견

### 2.1 🔴 모든 사진이 90도 회전되어 있다

세로 시험지를 가로 방향으로 들고 찍었습니다. 5장 전부입니다.
EXIF 방향 정보에만 의존하면 안 되고, **회전 자동 감지가 필수**입니다.

**대응**: 기준 마커의 배치는 비대칭이어야 합니다.
네 모서리를 모두 같은 모양으로 하면 0°/90°/180°/270°를 구분할 수 없습니다.

```
좌상단만 다른 모양(예: 이중 사각형)으로 만들어 방향을 확정합니다.

◧                              ■     ← 좌상단만 구분되는 마커
   ┌──────────────────────┐
   │                      │
   └──────────────────────┘
■                              ■
```

QR도 방향 판별에 쓸 수 있지만, QR이 안 읽히는 상황이 바로 정합이 필요한 상황이므로
마커 자체가 방향 정보를 가져야 합니다.

### 2.2 🔴 손에 들고 찍어 종이가 휜다

샘플 2·3은 손가락으로 시험지를 잡고 촬영해 종이가 곡면으로 휘었습니다.
**평면 homography로는 보정되지 않습니다.** 가운데 부분의 좌표가 수 mm씩 밀립니다.

**대응 (우선순위 순)**
1. **촬영 규칙으로 막는다** — "책상에 평평하게 놓고 찍기". 가장 싸고 확실합니다.
2. **품질 검사로 잡는다** — 마커 4점으로 계산한 사각형의 대각선 비율이 어긋나면
   휨으로 판단하고 재촬영을 요청합니다.
3. 곡면 보정(dewarping)은 Phase 1 범위에서 제외합니다. 비용 대비 효과가 낮습니다.

샘플 5는 책상에 평평하게 정면으로 찍혔고 상태가 확연히 좋습니다.
**이것을 촬영 가이드의 기준 예시로 삼습니다.**

### 2.3 🔴 흰 종이 위에 흰 종이

5장 중 4장에서 배경에 다른 시험지·교재가 깔려 있습니다.
문서 외곽 검출(edge detection)이 배경 종이와 대상 시험지를 구분하지 못합니다.

**대응**: 외곽 검출에 의존하지 않고 **기준 마커 4점만으로 정합**합니다.
이것이 원래 설계이며, 이 샘플들이 그 판단이 옳았음을 확인해줍니다.
촬영 가이드에는 "가능하면 어두운 색 책상 / 빈 공간에 놓고 촬영"을 넣되, 필수는 아닙니다.

### 2.4 🟡 인쇄된 첫 글자 + 학생 손글씨가 한 칸에 섞인다

샘플 1의 26~50번은 한국어 뜻을 보고 영단어를 쓰는데, **첫 글자가 인쇄되어 있습니다.**

```
28. 보호하다, 지키다; 경계, 경호원    g̲u̲a̲r̲d̲      ← 'g'는 인쇄, 'uard'는 손글씨
29. 점차적인, 단계적인               g̲r̲a̲d̲u̲a̲l̲
41. 문명; 문화                      c̲i̲v̲i̲l̲i̲z̲a̲t̲i̲o̲n̲
```

기획 문서에 없던 케이스입니다. crop 영역 안에 활자와 손글씨가 공존합니다.

**대응**: 오히려 **자동채점에 유리합니다.**
- 첫 글자가 확정되어 정답 후보가 크게 좁혀집니다
- 인쇄 글자는 형태가 일정해 손글씨 시작점을 찾는 기준이 됩니다
- 템플릿에 `prefix` 필드를 추가해, 인식 결과를 `prefix + 손글씨`로 조립해 비교합니다

```json
{ "label": "answer", "kind": "handwriting",
  "prefix": "g", "bbox": {...} }
```

### 2.5 🟡 답안이 여러 줄로 넘친다

샘플 2·3의 8번·10번은 긴 영작이라 답안이 2~3줄로 넘어갑니다.
줄 수가 학생마다 다릅니다.

**대응**: 문장형 답안 영역의 bbox는 **인쇄된 답안선 1줄이 아니라
"다음 문항 번호 직전까지"의 블록 전체**로 잡습니다.
문장형은 어차피 VLM이 이미지 전체를 읽으므로 넉넉한 영역이 안전합니다.

### 2.6 🟡 학생의 취소선·수정 흔적

샘플 3의 9·10번에는 인쇄된 힌트 단어에 학생이 줄을 그어 사용 표시를 했고,
답안 자체에도 지우고 다시 쓴 흔적이 있습니다.

**대응**: 이런 답안은 확신도를 낮춰 검수로 보냅니다.
취소선 감지를 별도로 구현하지는 않고, VLM 응답에
`has_corrections: true` 필드를 두어 판단 근거로 활용합니다.

### 2.7 🔴 악필 편차가 예상보다 크다

샘플 4는 **사람이 읽어도 상당 부분 판독이 어려운 수준**입니다.
같은 시험지의 샘플 2·3은 문제없이 읽히는 것과 대조적입니다.

이것이 이번 분석에서 가장 중요한 발견입니다.
**"인식 실패"는 예외가 아니라 정상 케이스로 설계해야 합니다.**

5장 중 1장이 이 수준이라면, 반 전체에서 **10~20%의 학생은 사실상 전 문항 검수**로
갈 수 있습니다. 이는 검수율 목표에 직접 영향을 줍니다.

**대응**
- 검수율 목표를 재조정합니다: 전체 30% → **문항 기준 20%, 단 학생 단위 편차 큼**
- 검수 화면에 **"이 학생은 전 문항 검수"** 모드를 둡니다.
  악필 학생의 답안지를 문항별로 하나씩 띄우는 것보다,
  원본 전체를 크게 띄우고 수기 채점하듯 처리하는 편이 빠릅니다.
- 학생별 인식 실패율을 누적해, 반복적으로 실패하는 학생은 자동으로 이 모드로 보냅니다.

### 2.8 🟡 채점 마크의 의미가 선생님마다 다르다

샘플들의 채점 표기가 일관되지 않습니다.

| 샘플 | 표기 | 추정 의미 |
|---|---|---|
| 1 | 빨간 `V` 체크 | 틀린 문항 |
| 1 | 빨간 `Ⓟ` | PASS |
| 2 | 파란 동그라미 (문항 번호) | ? — 점수 1/10과 개수가 안 맞음 |
| 3 | 빨간 동그라미 (문항 번호) | ? — 점수 8/10 |
| 5 | 분홍 동그라미 (문항 번호) | 정답 표시로 추정 (8개 = 8점) |

운영에는 영향이 없습니다(채점 **전에** 촬영하므로).
그러나 **Phase 0에서 이 답안지들을 정답 라벨로 쓰려면 반드시 확인해야 합니다.**
동그라미가 정답 표시인지 오답 표시인지 잘못 알면 벤치마크 결과 전체가 뒤집힙니다.

→ **선생님별 채점 표기 규칙을 문서화하는 것이 Phase 0의 첫 작업입니다.**

### 2.9 🟢 PASS 기준이 시험지에 이미 인쇄되어 있다

```
샘플 1:  /50 (cut-7)
샘플 2~4: (-3개까지 pass)
샘플 5:  /10 (컷 -3)
```

선생님들이 이미 명시적인 합격 기준을 쓰고 있습니다.
설계한 `pass_rule` 구조(`{"type":"max_wrong","value":3}`)가 그대로 맞아떨어집니다.
템플릿 등록 시 시험지에 적힌 값을 옮기기만 하면 됩니다.

### 2.10 🟢 상단 정보란이 표 형태로 규격화되어 있다

샘플 2~5는 `Class / 담당T / 학생이름 / 점수` 표가 상단에 고정되어 있습니다.
학생 이름란 위치가 일정해 **이름 crop → 명단 자동 추천**이 잘 작동할 구조입니다.

## 4. MVP 대상 재검토

기존 계획은 A유형(유&반의어 Test)을 1순위로 잡았습니다.
그러나 실제 샘플을 보면 **워드마스터 단어시험(샘플 1)이 더 나은 1순위**입니다.

### 왜 바뀌었나

| 항목 | 유&반의어 Test | **워드마스터 단어시험** |
|---|---|---|
| 답안 형태 | 선택형 + 한글 뜻 | 한글 뜻(1~25) + **영단어(26~50)** |
| 격자 규칙성 | 높음 | 높음 (2단 50문항) |
| 사용 빈도 | 보통 | **매우 높음 (Day별 상시)** |
| 정답 다양성 | 뜻 여러 개 인정 | **26~50번은 정답 1개** |
| 인쇄 힌트 | 없음 | **첫 글자 제공 → 후보 축소** |

특히 **26~50번(한글 뜻 → 영단어)이 전체에서 가장 자동채점하기 쉬운 문항군**입니다.

- 영어 손글씨 (한국어보다 인식 쉬움)
- 정답이 정확히 하나
- 첫 글자가 인쇄로 확정
- 철자 하나까지 정확히 맞아야 하므로 채점 규칙이 단순

### 수정된 Phase 1 범위

```
1순위:  워드마스터 단어시험 26~50번  (한글 뜻 → 영단어)
2순위:  워드마스터 단어시험 1~25번   (영단어 → 한글 뜻)
3순위:  유&반의어 Test              (선택형 + 뜻)
4순위:  본문 빈칸 Test
```

**한 시험지의 일부 문항군만 자동채점하고 나머지는 검수로 넘기는 것**이
처음부터 가능해야 합니다. 이것이 실제 도입 경로입니다.
"50문항 중 25문항이 자동으로 끝난다"만으로도 선생님 입장에서는 충분한 이득입니다.

> ⚠️ 기존 계획의 `MarkGrader`(선택형 마킹 판독)는 **Phase 1에서 쓸 곳이 없습니다.**
> 이번 샘플 5장에 선택형 문항이 하나도 없습니다.
> MarkGrader는 유&반의어 Test가 들어오는 시점으로 미룹니다.

## 5. 다음 단계

### 즉시
1. **선생님별 채점 표기 규칙 확인** — 동그라미가 정답인지 오답인지
2. **워드마스터 단어시험 답안지 30장 추가 수집** — 채점 전 상태로, 책상에 놓고 촬영
   - 악필 학생 답안을 반드시 포함 (전체의 20% 이상)
   - 무응답·수정 흔적 있는 것 포함
3. 각 답안지의 **정답 라벨**(선생님 채점 결과)을 표로 정리

### 이어서
4. 26~50번 영단어 칸만 crop해 인식 벤치마크 (`prefix` 활용 유무 비교)
5. 1~25번 한글 뜻 칸 인식 벤치마크
6. 기준 마커를 넣은 시험지를 인쇄해 다양한 각도·휨 상태로 촬영, 정합 오차 측정

### 판단 기준
26~50번 영단어 인식 정확도가 **95% 이상, 오인식률 1% 미만**이면 Phase 1을 시작합니다.
그 미만이면 인식기를 바꾸거나, 답안칸 규격(높이·간격)을 먼저 조정한 뒤 재측정합니다.

# 2차 분석 (답안지 약 50장)

**분석일**: 2026-08-05
**샘플**: 조교팀이 수집한 실제 답안지 약 50장 (대부분 **채점 전** 상태)
**촬영 품질**: 1차보다 확연히 좋음 — 책상에 평평하게, 정면, 나무 책상 배경.
**촬영 지시가 제대로 전달되었습니다.**

## 1. 🔴 가장 중요한 발견 — 시험지가 이미 자동 생성되고 있다

주력 시험지인 **유니크보카** 계열의 머리말이 이렇게 되어 있습니다.

```
┌─ 목동유쌤영어학원 ──────────────────  이름 [        ] ─┐
│  8/3(4) 월(화)_고2 독해해부반_유니크보카 DAY 25-28_커트 -8(오답필수)_김은진T
│  반 이름: 고2 독해해부반  ·  컷트라인: 8개 (최대 8개까지 오답 허용)
│  (Chapter 25,26,27,28) (유형 표제어, 연관어) (방향 영어→한글) (문항 수 140)
│  ┌────────┬──────────────┬──────────┬────────────────┐
│  │ 채점자 │              │ 채점 결과 │ ○ Pass  ○ Fail │
│  │ 재시험일│              │          │                │
└──┴────────┴──────────────┴──────────┴────────────────┘
```

**이건 사람이 손으로 만든 워드 파일이 아닙니다.** 칩(chip) 형태로 렌더링된
구조화 메타데이터 — 챕터 범위, 출제 유형, 출제 방향, 문항 수, 컷트라인 —
그리고 채점 결과·재시험일 기입란까지. **명백히 시스템이 생성한 출력물입니다.**

### 이게 왜 결정적인가

GradeSnap 설계에서 **가장 무겁고 가장 위험한 부분이 템플릿 등록**입니다.
문항 140개, 160개짜리 시험지의 답안 영역을 사람이 손으로 찍는 것은 불가능에 가깝고,
"템플릿 등록이 번거로워 아무도 안 쓴다"를 최상위 리스크로 잡아둔 이유가 그것입니다.

그런데 시험지를 만드는 시스템이 이미 있다면:

| 항목 | 손으로 등록할 때 | 생성 시스템과 연동할 때 |
|---|---|---|
| 문항 목록·정답 | 140개 수기 입력 | **이미 DB에 있음** |
| 답안 영역 좌표 | 140개 드래그 | **PDF를 그리는 쪽이 곧 좌표를 앎** |
| 출제 방향(영→한/한→영) | 문항별 지정 | **이미 메타데이터에 있음** |
| 컷트라인 | 수기 입력 | **이미 있음** (`컷트라인: 8개`) |
| QR·기준 마커 | 별도 삽입 후 재인쇄 | **생성 시 함께 인쇄** |

즉 **템플릿 편집기라는 기능 자체가 없어도 되고**, 인쇄용 PDF 재생성 절차도 사라집니다.
Phase 1에서 가장 큰 개발 항목(1.5주)과 가장 큰 리스크가 동시에 제거됩니다.

### 🚨 최우선 확인 사항

**다음 개발 판단은 전부 이 질문의 답에 달려 있습니다.**

1. 유니크보카 시험지를 만드는 시스템은 무엇입니까? (자체 개발 / 외부 솔루션 / 엑셀 매크로)
2. 누가 만들었고, 소스 코드와 DB에 접근할 수 있습니까?
3. 단어 데이터(표제어·뜻·챕터)와 출제 이력이 DB에 저장되어 있습니까?
4. 같은 시스템이 다른 시험지도 만듭니까? (`문법 백지 TEST`도 유사한 헤더 구조입니다)

**접근 가능하다면** → GradeSnap은 그 시스템의 "채점 모듈"로 붙는 것이 압도적으로 유리합니다.
**접근 불가능하다면** → 기존 계획대로 PDF 기반 템플릿 등록으로 갑니다.

두 경우의 설계가 상당히 달라지므로, 코드를 쓰기 전에 반드시 확인해야 합니다.

## 2. 단어시험 레이아웃이 최소 4가지

이 학원의 단어시험은 교재·선생님별로 양식이 다릅니다.

| 레이아웃 | 예시 | 답안 영역 | 자동채점 유리도 |
|---|---|---|---|
| **A. 밑줄형 2단** | 유니크보카, 보카클리어, CEDU | 인쇄된 밑줄 위 | 보통 |
| **B. 표/셀형** | 능률 VOCA, 수능완성 어휘 | 테두리로 구획된 셀 | **가장 높음** |
| **C. 셀 격자 4단** | 워드마스터 수능 2000 | 셀 | 높음 |
| **D. 4지선다** | 어휘끝 수능 UNIT 29-32 | ①②③④에 동그라미 | **가장 높음** |

**공통 구조는 하나입니다**: `문항번호 + 제시어 + 답안영역`의 반복.
레이아웃이 달라도 같은 추상화로 처리할 수 있습니다.

### 🟢 4지선다 시험지의 등장 — MarkGrader가 부활합니다

1차 분석에서 "선택형 문항이 하나도 없다"며 `MarkGrader`를 연기했는데, **틀렸습니다.**
`어휘끝 수능 UNIT 29-32`는 1~20번이 **4지선다**입니다.
단어 하나에 뜻 4개를 제시하고 학생이 정답에 동그라미를 칩니다.

```
1. pessimism
   ① 책임을 맡기다, 기소하다, 고소하다 (= accuse), ...
   ② 퇴비 , , , 퇴비를 주다 (= fertilize)
  ⓷ 비관주의, 비관론 (↔ optimism)      ← 학생이 동그라미
   ④ (정상가보다) 싸게 사는 물건, 흥정 , , 흥정하다
```

**이건 이 학원 전체에서 가장 자동채점하기 쉬운 문항 유형입니다.**
손글씨 인식이 아예 필요 없고, 마킹 판독만으로 100% 처리됩니다.
`MarkGrader`를 Phase 1로 되돌립니다.

## 3. 🔴 밑줄형의 치명적 문제 — 학생이 밑줄을 지키지 않는다

밑줄형 시험지에서 학생들이 답을 쓰는 위치가 제각각입니다.
실제 샘플에서 확인된 것만:

- **밑줄 위** (정상)
- **밑줄 시작 전, 제시어 바로 옆** — 밑줄은 텅 비어 있음
- **밑줄 아래 줄** — 다음 문항 영역을 침범
- **왼쪽 여백** — 답안 영역과 완전히 무관한 위치
- **두 줄에 걸쳐서** — 긴 뜻을 쓸 때

한 샘플에서는 20~30번 답을 전부 왼쪽 제시어 옆에 썼고 **밑줄은 모두 비어 있었습니다.**
밑줄에만 bbox를 잡았다면 이 학생은 11문항 연속 "무응답"으로 오채점됩니다.

**대응**: 밑줄형의 `bbox`는 **밑줄이 아니라 "문항 행 전체"** 로 잡습니다.
문항 번호 왼쪽 끝부터 단 오른쪽 끝까지, 다음 문항 번호 직전까지의 띠 전체입니다.
잉여 영역이 들어오지만, 답을 놓치는 것보다 훨씬 낫습니다.

> **표/셀형이 유리한 진짜 이유가 이것입니다.**
> 셀 테두리가 학생의 필기 위치를 물리적으로 강제합니다.
> 인식 기술의 문제가 아니라 **양식이 만들어내는 문제**입니다.

## 4. 문항 수가 최대 160개, 페이지는 최대 4장

| 시험지 | 문항 수 | 페이지 |
|---|---|---|
| 유니크보카 DAY 25-28 | **140** | 3 |
| 어휘끝 수능 UNIT 29-32 | **160** | 4 |
| 유니크보카 13-16 / 15-17 | 90 | 2 |
| CEDU Day22-24 / Day25-27 | 90 | 2 |

**손으로 좌표를 찍는 방식은 이 규모에서 성립하지 않습니다.**
§1의 생성 시스템 연동이 안 된다면, **답안 영역 자동 검출**이 필수 기능이 됩니다.

```
표/셀형  → 셀 테두리 검출 (OpenCV 선분 검출 + 교차점)
밑줄형   → 수평선 검출 후 문항 번호와 매칭
4지선다  → 원문자(①②③④) 위치 검출
```
검출 결과를 선생님이 **확인·수정만** 하는 방식이어야 합니다. 처음부터 찍는 게 아니라.

## 5. 그 외 관찰

### 🟡 무응답이 매우 흔하다 — 그리고 이건 좋은 소식
거의 모든 답안지에 빈칸이 있고, 많게는 10개 이상입니다.
**무응답은 OCR 없이 판정 가능하고, 확신도가 높습니다.**
잉크 픽셀이 임계 미만이면 즉시 오답 확정 — 검수도 필요 없습니다.
문항의 10~20%가 인식 부담 없이 처리된다는 뜻입니다.

### 🟡 취소선·덧칠 수정이 빈번하다
답을 쓰고 새까맣게 덧칠하거나 줄을 긋고 옆에 다시 쓴 경우가 많습니다.
`◼◼◼ depress`, `~~mobility~~ variety` 같은 형태입니다.
→ 수정 흔적이 감지되면 확신도를 낮춰 검수로 보냅니다.

### 🟡 학생 자가채점 표시(`V`)가 답안 옆에 있다
채점 전인데도 답 뒤에 `V` 표시가 붙은 답안지가 여럿입니다.
학생이 스스로 확인한 표시로 보입니다.
→ 인식 시 노이즈가 되므로, 프롬프트에 "답안 뒤의 체크 표시는 무시하라"를 명시합니다.

### 🟡 출제 방향이 한 시험지 안에서 섞인다
유니크보카는 헤더에 `방향 혼합`이라고 적혀 있고, 실제로 문항마다 다릅니다.
```
1. irritating  [한글 뜻 작성]     ← 영→한
2. a.짜증난     [영단어 작성]     ← 한→영
```
→ 문항 번호로 방향을 추론할 수 없습니다. **문항별 방향 정보가 템플릿에 필요합니다.**
(생성 시스템에는 이미 있을 값입니다.)

### 🟡 연필 작성이 대부분이다
거의 모든 답안이 연필/샤프입니다. 볼펜보다 대비가 현저히 낮습니다.
→ 전처리에 **대비 강화(CLAHE 등)** 를 반드시 넣습니다. 인식률에 직결됩니다.

### 🟢 채점 전 촬영이 잘 지켜졌다
1차와 달리 대부분 채점 표시가 없습니다. 인식 방해 요소가 사라졌습니다.
다만 이 때문에 **정답 라벨이 없습니다** — 벤치마크에 쓰려면
선생님이 이 답안지들을 채점한 결과를 별도로 받아야 합니다.

### 🟡 문법 백지 TEST는 별도 유형
`Level 3 문법 백지 TEST` 계열은 본문 곳곳에 빈칸이 흩어진 D유형입니다.
표 안 분류 문제, O/X 선택, 문장 전환이 한 장에 섞여 있습니다.
헤더 구조가 유니크보카와 유사해 **같은 시스템 출력일 가능성**이 있습니다 (확인 필요).
자동채점은 Phase 3 대상이지만, 답안 위치는 의외로 규칙적입니다.

## 8. 추가 관찰 (마지막 배치)

### 🟢 영작 시험이 생각보다 훨씬 유리하다 — C유형 난이도 하향
`영작클리닉 Ch.03 수동태2` 샘플의 학생 답안은 **필기체지만 매우 일정하고 깨끗**합니다.
1차 분석의 CLINIC 영작 샘플(악필)과 정반대입니다.

더 중요한 것은 **문항에 조건이 명시되어 있다**는 점입니다.

```
2. 큰 스테이크가 웨이터에 의해 손님들에게 제공되었다. (11단어 / steak / bring / guests)
   → A big steak was brought to the guests by the waiter.      (= 11단어 ✓)
```

`(11단어 / steak / bring / guests)` — **단어 수와 필수 사용 단어가 문제에 인쇄되어 있습니다.**
이건 채점에 그대로 쓸 수 있는 검증 조건입니다.

```
1. 단어 수 일치 여부      → 기계적 검증, AI 불필요
2. 필수 단어 포함 여부    → 기계적 검증, AI 불필요
3. 문법·어형 정확성       → AI 판정
```

앞의 두 가지가 자동으로 걸러지므로 AI의 부담과 관대함 위험이 크게 줄어듭니다.
**`SentenceGrader`에 `required_words`와 `word_count` 필드를 추가합니다.**

### 🟢 문법 백지 TEST의 표 부분은 자동채점 가능
`Chapter 4. 수동태` p.3의 구동사 표는 `구동사 | 해석 | 수동태`가 3열로 반복되는
**완전한 셀 구조**입니다. 좌표가 명확하고 답이 짧습니다.

문법 백지 TEST 전체를 D유형(어려움)으로 분류했지만, **표 부분만은 Phase 1~2 수준**입니다.
"한 시험지 안에서 자동채점 가능한 문항군만 처리"라는 원칙이 여기서도 유효합니다.

### 🟡 시험지 헤더가 전부 구조화된 표 형태다
확인된 모든 시험지가 상단에 `반명 / 학생명 / 날짜 / 점수 / 커트라인 / P·F`
또는 `Class / 담당T / 학생이름 / 채점자` 표를 갖고 있습니다.
양식은 조금씩 다르지만 **전부 시스템이 생성한 것으로 보입니다.**
(`고등 BASIC[23]`, `2026.07.23` 같은 자동 삽입 필드도 확인됨)

→ §1의 확인 사항이 유니크보카 하나가 아니라 **학원 시험지 전반**에 해당할 가능성이 큽니다.
