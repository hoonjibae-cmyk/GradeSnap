# 12. 페이지 단위 채점으로 전환 — 설계 결정 기록

**결정일**: 2026-08-07
**상태**: 확정. 03·05·07의 파이프라인 설계를 이 문서가 대체합니다.

---

## 12.1 무엇을 바꾸는가

```
[기존]  사진 → 마커 정합 → QR 식별 → 템플릿 좌표로 crop → 칸 하나씩 인식 → 규칙 채점
[신규]  사진 → AI가 페이지 전체를 문항별로 전사 → 규칙 채점
                                  ↓ 확신도 낮은 문항만
                            부분 확대 재질의 / 교사 검수
```

**템플릿 등록·기준 마커·homography 정합·좌표 crop이 전부 없어집니다.**

---

## 12.2 왜 바꾸는가 — 기존 설계의 근거 세 개 중 둘이 무너졌습니다

기존 설계는 "기계가 앞에, AI는 칸 하나만 읽는다"였습니다. 근거는 셋이었습니다.

### ① "손글씨 인식은 어려우니 정보를 최대한 좁혀줘야 한다" → ❌ 반증됨

샘플 분석 과정에서 **템플릿도 좌표도 crop도 없이 사진만 보고** 오답을 짚었고,
선생님 채점과 대조했습니다.

| 시험지 | 사진만 보고 판정 | 선생님 채점 | 결과 |
|---|---|---|---|
| 유니크보카 (하수정T) | 오답 9·20·22·34 = 4개 | `Ⓟ`, 컷 4.8 | 일치 |
| BOOSTER VOCA (이서영T) | 오답 12개 | `-12`, `Ⓕ` | **정확히 일치** |
| M6 Day14-16 (이승희T) | 오답 16·39·46·47 = 4개 | `-4`, `Ⓟ` | **정확히 일치** |

세 장의 **양식이 전부 달랐습니다**(표형 / 밑줄형 / 양방향 혼합형).
사전 등록도 학습도 없었습니다.

### ② "AI는 비싸니 필요한 부분만 보내야 한다" → ❌ 계산이 반대

**실측했습니다** (50문항 A4 1장, Opus 5, 2026-08-07 → [12.11](#1211-배관-검증-2026-08-07)).

| 방식 | 토큰 | Opus 5 |
|---|---|---|
| **페이지 통째** | 입력 4,993 + 출력 3,306 | **$0.118 (실측)** |
| 칸별 crop 50개 | 입력 50,000 + 출력 2,000 | $0.30 (추정) |

통짜가 여전히 **2~3배 쌉니다.** 칸별로 자르면 "이건 답안 칸이다"라는 지시와 시스템
프롬프트를 50번 반복해 보내야 하기 때문입니다.

실측 토큰으로 다시 계산한 장당·월 비용:

| 모델 | 장당 | 하루 100장 | 하루 300장 |
|---|---:|---:|---:|
| Claude Opus 5 | **$0.118** | $260 | $779 |
| Claude Sonnet 5 (8/31까지 도입가) | $0.043 | $95 | $284 |
| GPT-5.6 Terra | $0.050 | $110 | $329 |
| Gemini 3 Flash | $0.012 | $27 | $82 |
| Gemini 3.1 Flash-Lite | $0.006 | $14 | $41 |

**출력 토큰이 비용의 70%입니다.** 문항당 9개 필드를 뱉기 때문입니다.
Batch API를 쓰면 절반이 되고, 스키마를 줄이면 더 줄어듭니다.

> 처음 추정치는 출력 1,500토큰 기준 $0.064였습니다. 실측이 3,306토큰이라 약 2배입니다.
> **추정으로 설계 결정을 하지 않은 것이 다행이었습니다.**

### ③ "AI가 50문항을 한 번에 세면 행이 밀릴 수 있다" → 🟡 **유효. 이것만 남았습니다**

무응답 칸에서 한 줄 밀려 읽으면 그 아래가 전부 어긋나고, **조용히 그럴듯한 점수가
나옵니다.** crop 방식은 물리적으로 이게 불가능했습니다. 이 안전성은 실제로 있었습니다.

→ 좌표 없이 막는 방법은 12.4에 있습니다.

## 12.3 이 전환이 없애는 리스크

로드맵의 **최상위 리스크가 사라집니다.**

> "③이 시스템의 생사를 가릅니다. 선생님이 매회 시험지를 새로 만들고, 공유되는 것은
> 상단 헤더 표뿐입니다. **등록 시간이 채점 절감 시간보다 길면 도입할 이유가 사라집니다.**"
> — [07 §0.0b](07-roadmap.md)

등록이 없어지면 이 리스크 자체가 없어집니다. 시험지 3분류(①생성기 ②고정세트 ③매회신규)는
**등록 비용을 기준으로 나눈 분류**였는데, 등록 비용이 0이 되면 셋의 구분이 의미를 잃습니다.

부수 효과:
- **양식이 매번 바뀌어도 상관없습니다.** 이게 이 학원의 실제 조건입니다
- 기준 마커·QR을 인쇄물에 넣을 필요가 없습니다 → [06 양식 가이드](06-exam-form-guide.md)의 대부분이 불필요
- 90도 회전·종이 휨 대응이 전처리 문제에서 모델의 강건성 문제로 바뀝니다
- **샘플 수집 부담이 사라집니다** — 템플릿을 만들 필요가 없으니 시험지 PDF도, 좌표도 필요 없습니다

## 12.4 남는 진짜 제약 셋과 대응

### 🔴 행 밀림 — 유일한 치명적 실패 모드

무응답 칸을 건너뛰고 다음 답을 당겨 쓰면 아래가 전부 어긋납니다.
**좌표 대신 인쇄된 글자를 정합 기준으로 씁니다.**

모델에게 답만 내놓게 하지 않고, **문항 번호와 인쇄된 제시어를 함께** 출력하게 합니다.

```json
{"no": "38", "prompt": "전문적인, 전문직의", "written": "propessional", "blank": false}
```

`prompt`가 우리가 아는 38번과 다르면 그 자리에서 밀림이 드러납니다.
제시어는 인쇄 활자라 잘못 읽을 일이 거의 없어, 좌표보다 오히려 튼튼한 기준입니다.

교차 검증 세 가지를 `grade_page.py`의 `check_drift()`가 자동으로 겁니다.

| 검사 | 내용 | 사람 입력 |
|---|---|---|
| 번호 연속성 | 1..N이 빠짐없이 이어지는가 | 불필요 |
| 개수 대조 | 머리말에 인쇄된 총 문항 수와 전사 개수가 맞는가 | 불필요 (머리말에서 읽음) |
| **첫 글자 대조** | 첫 글자가 인쇄된 문항은 답이 그 글자로 시작해야 한다 | 불필요 |
| **언어 대조** | `ko2en` 칸에 한글 답이 들어오면 안 된다 | 불필요 |
| 제시어 대조 | 각 번호의 제시어가 정답표와 같은가 | 정답표가 있을 때만 |

**앞의 넷은 사람 입력이 전혀 필요 없습니다.** 특히 첫 글자·언어 대조가 강력합니다 —
38번의 인쇄된 `p` 자리에 39번 답 `victim`이 들어오면 그 자리에서 드러나고,
`한글→영어` 칸에 한글 답이 들어와도 마찬가지입니다. 한 시험지에 양방향이 섞여
있는 경우가 많아([08](08-sample-analysis.md)) 이 검사가 잘 걸립니다.

### 🟡 해상도

A4 한 장에 50문항이면 답안 한 칸이 40~80픽셀 높이입니다. 연필 글씨엔 빠듯할 수 있습니다.
**실측이 필요합니다.** 부족하면 페이지를 위아래로 **겹쳐서 2~4등분**해 보냅니다
(`--split 2`). 단순 등분이라 좌표는 여전히 필요 없고, 비용이 2~4배가 되어도
칸별 crop보다 쌉니다.

### 🟡 비결정성

같은 사진을 두 번 채점하면 다른 결과가 나올 수 있습니다. 규칙 기반은 항상 같았습니다.
`--repeat N`으로 흔들리는 정도를 측정하고, **흔들린 문항은 확신도와 무관하게 검수로
보냅니다.** 채점 결과와 입력 사진을 함께 보관해 재현·감사 가능하게 합니다.

### ⚪ 관대함 — 방식과 무관하게 남습니다

정답을 알려주고 읽히면 틀린 걸 맞다고 읽습니다.
**전사와 판정을 분리**해 통제합니다. AI에게는 "쓰인 글자를 옮겨라"만 시키고,
정오는 별도 단계에서 정합니다. `grade_page.py`가 `transcribe`와 `judge`를
다른 호출로 분리한 이유입니다.

## 12.5 채점 마크 판독 — 확인 표시와 오답 표시를 구분해야 합니다

선생님 채점 결과를 정답 라벨로 쓰려면 채점 마크를 읽어야 하는데, 여기 함정이 있습니다.
**모든 선생님이 표시를 두 종류 씁니다.**

| 선생님 | 확인 표시 (거의 전 문항) | 오답 표시 (소수) | 검증 |
|---|---|---|---|
| 하수정T | 문항번호에 동그라미 | **V 체크** | 오답 4 / 컷 4.8 → `Ⓟ` ✅ |
| 이서영T | 없음 | **긴 사선** | `-12` 표기와 내용 채점 일치 ✅ |
| 이승희T | 답 끝에 작은 점 | **긴 사선** | 오답 4 / 컷 -7 → `Ⓟ` ✅ |
| 박채영T | 문항번호에 동그라미 | (이 장엔 없음) | 오답 0 → `Ⓟ` |

**동그라미는 정답 표시가 아닙니다.** 어법&구문 Review Test에서는 명백히 틀린 11번에도
동그라미가 있었습니다. 거의 모든 문항에 붙는 표시는 "채점함"이지 정오가 아닙니다.
이걸 오답으로 읽으면 결과가 통째로 뒤집힙니다.

→ `grade_page.py marks`가 이 구분을 먼저 하도록 프롬프트에 못 박아 두었습니다.

## 12.6 철자 관대 채점 — 정답표보다 선생님이 넓습니다

실제 답안지에서 확인된 사례입니다.

| 시험지 | 학생이 쓴 것 | 정답 | 선생님 판정 |
|---|---|---|---|
| EBS 올림포스 | `efrigiator` | refrigerator | **정답** |
| EBS 올림포스 | `expectution` | expectation | **정답** |
| M6 Day14-16 | `propessional` | professional | **정답** |
| M6 Day14-16 | `labortary` | laboratory | **정답** |
| 유니크보카 | `undo → 열다` | 원상태로 돌리다 | **정답** |

네 장에서 다섯 건입니다. 우연이 아니라 **관행**입니다.

이것이 뜻하는 바 두 가지:

1. **채점 규칙(rubric)이 시험지마다 다릅니다.** "철자 엄격 / 관대"를 시험 단위로 정할
   수 있어야 합니다. AI가 정하는 게 아니라 선생님이 정하는 값입니다.
2. **"선생님이 정답 처리했으니 학생이 정답을 정확히 썼다"는 추론이 깨집니다.**
   [11 §11.3](11-recognition-benchmark.md)의 자동 라벨링이 여기 걸립니다.

## 12.8 새 벤치마크 — 새 샘플이 필요 없습니다

재는 것은 하나입니다.

> **답안지 사진 한 장을 통째로 넣었을 때, 선생님 채점과 몇 % 일치하는가.**

필요한 것은 **채점 전 사진 + 채점 후 사진 한 쌍**뿐입니다. 이미 6쌍 확보돼 있습니다.
템플릿·좌표·시험지 PDF가 필요 없으므로 [11 §11.5](11-recognition-benchmark.md)의
막힌 지점이 사라집니다.

```bash
# 폴더 하나로 전부 — 짝짓기부터 집계까지
python3 tools/run_bench.py --dir samples/ --dry-run   # 짝짓기만 확인 (돈 안 씀)
python3 tools/run_bench.py --dir samples/ --out bench/
```

짝짓기는 사람이 안 합니다. 파일명을 정렬해 두 장씩 묶고, **둘 중 빨간펜이 많은 쪽을
'채점 후'로** 봅니다. 파일명을 고칠 필요도, 순서를 맞출 필요도 없습니다.

단계를 따로 돌리려면:

```bash
python3 tools/grade_page.py transcribe --image before.jpg --out t.json
python3 tools/grade_page.py marks      --image after.jpg  --out m.json
python3 tools/grade_page.py judge --transcript t.json --marks m.json
```

측정 항목:

| 지표 | 정의 | 판단 |
|---|---|---|
| **선생님 채점 일치율** | 문항 단위로 정오가 같은 비율 | 주 지표 |
| 우리만 오답 | 선생님은 맞다 했는데 우리는 틀렸다 함 | 대부분 철자 관대 채점 → rubric으로 흡수 |
| 선생님만 오답 | 선생님은 틀렸다 했는데 우리는 맞다 함 | **치명적.** 놓친 오답 |
| 밀림 경보 | `check_drift()` 경보 발생 장수 | 0이어야 함 |
| 비결정성 | 같은 사진 3회 중 답이 흔들린 칸 수 | 검수 라우팅 기준 |
| 장당 비용·시간 | | 운영 가능성 |

**Phase 1 착수 기준(2차 개정, 2026-08-07)**

> **처음 기준이 틀렸습니다.** 문항 단위 "놓친 오답 1% 미만"은 고부담 채점에서
> 빌려온 잣대였습니다. 이건 생기부에 들어갈 점수가 아니라 **수업 내 시험 하나**이고,
> 학생에게 일어나는 일은 **집에 가느냐 남아서 재시험을 보느냐** 뿐입니다.

### 결정 단위는 문항이 아니라 답안지 한 장의 PASS/FAIL입니다

문항 한둘이 어긋나도 **커트라인에서 멀면 결정은 안 바뀝니다.**
실측 pair3이 그 예입니다 — 선생님 13개, 우리 12개로 한 개를 놓쳤는데
커트라인이 8개라 양쪽 다 FAIL입니다. **학생에게 일어난 일은 똑같습니다.**

결정이 뒤집히는 건 **커트라인 근처에 있을 때뿐**입니다. 그 답안지만 사람이 보면 됩니다.
`compare()`가 커트라인 ±2 안에 든 장을 `near_boundary`로 표시합니다.
커트라인은 머리말에 인쇄돼 있어(`-8 까지 pass`, `-10%까지 PASS`, `커트라인 -7개`)
`parse_cut()`이 그대로 읽습니다. 조교가 입력할 것은 없습니다.

### 산출물이 둘이고, 요구 정확도가 다릅니다

| 산출물 | 결정 | 틀리면 | 요구 |
|---|---|---|---|
| **PASS/FAIL** | 집에 가느냐 재시험이냐 | 학생이 잘못 남거나 잘못 감 | **높게** |
| 오답 목록 | 뭘 다시 외우느냐 | 단어 한둘을 덜/더 복습 | 낮아도 됨 |

하나로 묶어 재던 것이 잘못이었습니다.

### 기준

| # | 기준 | 왜 |
|---|---|---|
| ① | **PASS/FAIL 일치 ≥ 97%** | 본 지표. 학생에게 실제로 일어나는 일 |
| ② | 경계선 검수율 ≤ 25% | **정확도가 아니라 운영 비용.** 이 장들은 사람이 본다 |
| ③ | 오답 목록 — 놓친 오답 ≤ 3% | 복습 범위가 조금 어긋나는 정도 |
| ④ | 밀림 경보 0장 | 밀리면 한 장이 통째로 무의미해진다 |

②는 낮을수록 좋은 게 아니라 **감당 가능하면 됩니다.** 30장 중 7장을 사람이 보는 건
50장을 전부 손으로 채점하던 것에 비하면 여전히 큰 절감입니다.

### 🔴 이 기준은 출시 전에 증명할 수 없습니다

장 단위 PASS/FAIL 일치율을 몇 장으로 확신할 수 있는지 계산해 봤습니다.
(Wilson 95% 신뢰구간 하한)

| 장 수 | 불일치 | 관측 | 신뢰구간 하한 | 97% 주장 |
|---:|---:|---:|---:|:--:|
| 7 | 0 | 100% | 64.6% | ❌ |
| 30 | 0 | 100% | 88.6% | ❌ |
| 100 | 0 | 100% | 96.3% | ❌ |
| 200 | 4 | 98.0% | 95.0% | ❌ |

**200장을 모아도 못 합니다.** 장 단위 지표는 표본 하나가 통째로 한 장이라
같은 확신을 얻는 데 문항 단위보다 훨씬 많은 표본이 듭니다.

그래서 결론이 바뀝니다.

> **출시 전 측정으로 얻을 수 있는 것은 "명백한 실패가 없다"까지입니다.**
> 30장이면 그건 됩니다. 97%라는 확신은 **운영 데이터로만** 얻을 수 있습니다.

이건 나쁜 소식이 아니라 **일정을 다시 짜라는 신호**입니다. 하루 300장이 나오는
학원에서 실사용 첫 달이면 수천 장이고, 그게 진짜 벤치마크입니다.
출시 전에 못 얻을 확신을 기다리며 착수를 미루면 그 데이터는 영영 안 생깁니다.

대신 **검수 범위를 데이터에 맞춰 좁혀 갑니다.**

| 시기 | 자동 확정 | 사람이 보는 것 |
|---|---|---|
| 1~2주차 | 없음 | **전 장 검수.** 시스템 결과를 보되 선생님이 확정 |
| 3~4주차 | 커트라인에서 먼 장 | 경계선 ±2 + 밀림 경보 + 낮은 확신도 |
| 이후 | 위 + 경계선 일부 | 누적 일치율을 보고 폭을 줄임 |

1~2주차에도 이득은 있습니다 — 선생님이 백지에서 채점하는 게 아니라
**채점 결과를 확인**하는 일이 됩니다. 그리고 그 2주가 수천 장짜리 벤치마크입니다.

### 그래도 남는 두 가지

**신뢰.** 선생님이 우연히 들춰보다 오채점을 발견하면 시스템을 안 믿게 됩니다.
"혹시 몰라서 전부 다시 확인"이 시작되면 이 시스템은 존재 이유를 잃습니다.
낮은 기준이 정당한 것과, 오채점을 발견해도 괜찮은 것은 다릅니다.

**경계선 학생.** 오차가 결정을 뒤집는 학생은 정확히 **커트라인에 걸린 학생**이고,
그 학생이야말로 재시험 여부가 중요한 학생입니다. ②의 검수가 이걸 받습니다.

처음에는 "인식 정확도"를, 다음에는 "문항 단위 채점 일치율"을 기준으로 삼았습니다.
둘 다 수단이었습니다. **목적은 선생님과 같은 결정에 도달하는 것**이고,
그 결정은 문항이 아니라 답안지 한 장의 PASS/FAIL입니다.

재현되지 않았습니다.

### 놓친 오답 4건은 네 건이 아니라 둘 + 둘입니다

**① 2건은 측정 도구의 결함이었습니다 (1번 시험지).**
이 시험지는 번호가 `1`~`14` 다음 `1)` `2)` `3)`으로 다시 시작합니다. 두 가지가 터졌습니다.

- 번호에서 숫자만 뽑아 비교해 `1)`이 `1`과 충돌 → **없는 중복 경보**
- 마크 판독이 번호 대신 `'1) 동명사만 목적어로 쓰는 동사 - decide'` 같은 **산문**을 반환 →
  전사된 어느 문항에도 붙지 않는데 `compare()`가 그대로 **놓친 오답**으로 셈

두 번째가 심각합니다. **두 결과를 맞출 수 없는 것과 오답을 놓친 것은 다릅니다.**
섞으면 판정 지표가 조용히 부풀어 결론 전체가 못 믿을 것이 됩니다.

고친 내용:

| 고침 | 내용 |
|---|---|
| 번호 비교 | 숫자만 뽑지 않고 **인쇄된 표기 그대로**. `1)` ≠ `1` |
| 연속성 검사 | **절 단위로.** 번호가 도로 작아지면 새 절로 봄 |
| `compare()` | 전사에 없는 마크는 `unmatched_marks`로 분리. **놓친 오답에 안 넣음** |
| `read_marks()` | 전사된 번호 목록을 넘겨 **그 안에서만** 고르게 함 |
| `run_bench` 집계 | 대조가 깨진 장은 **합계·판정에서 제외**하고 사유를 밝힘 |
| 작은 장 각주 | 15문항에서 1개 어긋나면 6.7%p — 분모를 같이 보이게 |

**② 2건은 진짜입니다 (3번 시험지).** 그리고 원인이 서로 다릅니다.

**17번 `intention` → 학생 `의도하다`.** 우리 판정기가 정답으로 봤고, 근거가
"명사를 동사로 썼으나 뜻은 통함"이었습니다. 관대함이 맞는데, **원인은 모델이 아니라
제 프롬프트였습니다.** 판정 규칙에 이렇게 적혀 있었습니다.

> `en2ko`는 뜻이 통하면 정답입니다. 'classify → 분류하다'와 '분류' 둘 다 정답입니다.

`classify`는 동사라 두 표기 다 자연스럽지만, 이 규칙이 **"품사가 달라도 뜻이 통하면
정답"으로 일반화**됩니다. 모델은 지시를 따랐고 지시가 틀렸습니다.
→ 품사가 바뀌면 오답이라는 규칙을 명시하고 예시를 고쳤습니다(`intention → 의도하다`는 오답).

**4번 `viewpoint` → 학생 `관점`.** 관점은 맞는 답인데 선생님이 오답 처리했습니다.
설명이 셋 중 하나입니다.

1. 선생님의 오채점
2. **마크 판독이 사선을 이웃 문항에 잘못 붙임** ← 실제로 의심됩니다
3. 학생 글씨가 관점이 아닌 다른 것

[08](08-sample-analysis.md) 분석 당시 이 사진에 대해 이렇게 적어뒀습니다 —
**"사선이 칸 경계에 걸쳐 있어 어느 문항인지 사람도 헷갈립니다. 4번과 5번 사이가 그렇습니다."**
사람이 헷갈린 자리에서 기계도 헷갈린 것이라면 2번입니다. 사진과 마크 판독 원자료를
대조해야 갈립니다.

### 🔴 그래서 드러난 것 — 선생님 채점은 완전한 정답 라벨이 아닙니다

[12.6](#126-철자-관대-채점--정답표보다-선생님이-넓습니다)에서 선생님이 **관대한 쪽으로**
정답표를 벗어난다는 걸 확인했습니다. 4번은 **엄격한 쪽으로도** 벗어날 수 있음을 보여줍니다.

> **일치율 100%가 목표가 아닙니다.** 불일치가 나오면 어느 쪽이 맞는지를 따져야지,
> 선생님이 항상 옳다고 두면 우리가 더 정확한 경우까지 실패로 셉니다.

`--strict` 같은 채점 규칙이 필요한 이유이고, Phase 1의 검수 화면이 필요한 이유입니다.

### 시험지 유형별 결론 — 아직 이르다

"단어시험 96~100%, 문법·영작 73~93%"이라는 읽기가 나왔지만 **치명 지표로 보면 반대입니다.**

**4·5번은 놓친 오답이 하나도 없습니다.** 어긋남 각 1개는 둘 다 '우리만 오답' —
우리가 선생님보다 **엄격했던** 쪽입니다. 낮은 백분율은 분모가 15와 10이라서입니다.

그건 유형 판단의 근거가 되지만, 4·5번을 같은 줄에 세울 근거는 이 데이터에 없습니다.

→ **"자유 나열형은 대상 밖"은 유지. "문법·영작 시험지 전반이 약하다"는 보류.**
어법·영작 시험지를 몇 장 더 봐야 갈립니다.

## 12.13 🔴 전사가 원문을 지키지 않습니다 (2026-08-07, 실측 2차)

**이 문서에서 가장 중요한 절입니다. 설계 가정 하나가 깨졌습니다.**

[12.11](#1211-배관-검증-2026-08-07)에서 이렇게 적었습니다.

> 모델은 존재하지 않는 단어를 실재 단어로 고치지 않았습니다. 다만 **인쇄 활자
> 한 건이므로 증거로는 약합니다.** 고쳐 읽고 싶은 유혹은 애매한 손글씨에서
> 훨씬 강해집니다.

실제 손글씨에서 반례가 나왔습니다.

| 문항 | 종이에 쓰인 것 | 전사가 내놓은 것 | 편집거리 | |
|---|---|---|:--:|:--:|
| pair6 #19 (기대) | `expect**u**tion` | `expect**a**tion` | 1 (u→a) | ❌ |
| pair3 #4 (viewpoint) | `관**전**` | `관**점**` | 1 (ㄴ→ㅁ) | ❌ |
| pair6 #10 (냉장고) | `refrigiator` | `refrigiator` | 2 | ✅ |

**한 글자만 고치면 실재 단어가 되는 경우에만 고쳐 읽었습니다.**
두 글자를 고쳐야 하는 `refrigiator`는 그대로 살아남았습니다.
픽셀을 읽는 것이 아니라 **기대하는 답으로 수렴**하고 있습니다.

### 검증 방법 — 두 독립 출처가 일치합니다

`관전`과 `관점`은 사람이 봐도 갈리는 차이라 글리프 대조로 확인했습니다.

- 같은 학생의 다른 문항(`drained`, `refrigiator`, `native`)에서 `a`는 **닫힌 원**입니다
- 19번의 해당 글자는 **위가 열려 있어** `u` 모양입니다
- 4번은 두 음절 모두 받침이 **곡선 ㄴ**이고 닫힌 사각 ㅁ이 아닙니다

여기에 [08](08-sample-analysis.md) 샘플 분석 당시 사람이 손으로 기록해 둔
`expectution`이 독립적으로 일치합니다. 그리고 **재실행에서 같은 고쳐 읽기가
재현**됐습니다(4번, 2회 연속). 표본 흔들림이 아닙니다.

### 왜 심각한가 — 12.4의 대책이 여기를 못 막습니다

`transcribe`와 `judge`를 다른 호출로 나눈 이유는 "정답을 알려주면 봐준다"를
막기 위해서였습니다. **그런데 이 손상은 judge가 돌기 전에 이미 끝나 있습니다.**
호출을 나눠도 전사기가 이미 답을 알고 있으면 소용이 없습니다.

증거가 있습니다. 채점 규칙 회귀 테스트가 **20/20 통과**했는데도 4번은 여전히
`관점`으로 나왔습니다. 규칙은 멀쩡했고, 규칙이 문제가 아니었습니다.

**정답표를 안 줘도 막히지 않습니다.** 전사 프롬프트에는 정답을 넣지 않았습니다.
그런데 시험지에 인쇄된 제시어(`기대`, `viewpoint`)가 페이지에 있고, 모델은
어휘를 알고 있어 **답을 스스로 유도합니다.** 가릴 수 없습니다.

| | 확신도 |
|---|---:|
| 고쳐 읽은 pair3 #4 | **0.90** |
| 고쳐 읽은 pair6 #19 | **0.93** |
| 재실행에서 흔들린 pair7 #9 | 0.75 |

**모델은 고쳐 읽으면서 확신에 차 있었고, 정직하게 흔들린 칸은 낮은 점수를 줬습니다.**
검수 라우팅을 확신도에만 걸면 이 부류는 전부 자동 확정으로 통과합니다.
[README 원칙 3](../README.md)("확신도가 낮으면 교사에게 넘긴다")은 여전히 필요하지만
**충분하지 않습니다.**

### 숫자를 다시 읽어야 하는 부분

**pair6의 100%는 우연입니다.** 학생은 틀리게 썼고(`expectution`), 선생님은 철자
관대 채점으로 정답 처리했고, 우리는 **오류를 아예 못 봐서** 정답 처리했습니다.
결론만 같습니다. 같은 100%인데 의미가 정반대입니다.

**pair3 #4는 마크 판독 오류가 아니었습니다.** 빨간 사선이 4번 칸을 정확히 지나고
선생님이 옳았습니다. [12.12](#1212-첫-실측-2026-08-07--답안지-7쌍)에서 "선생님
오채점이 의심된다"고 적은 것은 **틀렸습니다.** 원인은 전사였습니다.
→ 다만 "선생님 채점이 완전한 정답 라벨은 아니다"라는 12.12의 결론 자체는
철자 관대 채점([12.6](#126-철자-관대-채점--정답표보다-선생님이-넓습니다))으로 여전히 유효합니다.

### 다음 — 읽히는 방식으로 고칠 수 있는지부터

`probe_reading.py`가 같은 사진·같은 문항에 **읽히는 방식만 바꿔** 넣고 원문 보존율을 잽니다.

| 전략 | 발상 |
|---|---|
| `baseline` | 지금 프롬프트 (기준선) |
| `spell` | 한 글자씩 분해해 적게 함 — 단어 완성 관성을 끊는다 |
| `diff` | "정답과 다른 점이 있는지 글자 단위로 대조하라" — 읽기를 대조로 바꾼다 |
| `doubt` | "오타가 흔하다. 실재 단어로 보여도 의심하라" |

**결과에 따라 갈립니다.**

- 어느 전략이 지켜내면 → **프롬프트로 고칠 수 있다.** 그 전략을 기본으로 채택
- 전부 못 지키면 → 프롬프트로는 안 된다. 다음 수를 봐야 한다
  - 확신도 대신 **두 방식의 불일치**를 검수 신호로 쓴다 (한쪽만 고쳐 읽으면 드러남)
  - 철자가 걸린 칸만 **잘라서 따로** 읽힌다 — 버렸던 crop 방식이 *검증용*으로 되살아난다
  - 철자 엄격 채점이 필요한 문항군은 자동채점 대상에서 뺀다

**셋 다 이 발견이 없었으면 나오지 않을 선택지였습니다.**

## 12.9 개인정보 — 머리말은 가리지 않고, 동의를 받습니다

**결정: 사진을 통째로 보냅니다. 학부모 동의·고지로 처리합니다.** (2026-08-07)

### 왜 가리지 않기로 했나

처음에는 머리말을 자동으로 덮어 이름을 안 보내는 쪽으로 설계했습니다. **틀렸습니다.**
머리말에 있는 건 이름 하나가 아니라 일곱 개입니다.

```
8/3(4) 월(화)_고2 독해해부반_유니크보카 DAY 25-28_커트 -8(오답필수)_김은진T
반 이름: 고2 독해해부반 · 컷트라인: 8개 · (문항 수 140) · 이름: [박준희]
```

| 필드 | 없으면 |
|---|---|
| 반 이름 | 조교가 고름 |
| 시험명·회차 | 조교가 고름 |
| 담당 선생님 | 조교가 고름 |
| 날짜 | 조교가 고름 |
| 커트라인 | 조교가 입력 |
| 문항 수 | 조교가 입력 |
| **학생 이름** | ← 문제되는 건 이것 하나 |

**하나를 가리려고 여섯을 버리는 거래였습니다.** 그리고 그 여섯은 전부 조교가 손으로
넣어야 할 값이 됩니다. 이 제품의 전제는 **"시험지 가져오면 찍고 끝"**인데,
장마다 입력을 요구하는 순간 그 전제가 무너집니다.

**머리말을 보내면 조교 입력이 0이 됩니다.** 사진 한 장에서 반·시험·선생님·커트라인·
문항 수가 다 나옵니다. 머리말은 가려야 할 위험이 아니라 **자동화의 핵심 자산**입니다.

### 대신 지킬 것

- **학부모 동의·고지** — 개인정보 처리방침에 국외 이전 항목을 넣습니다
- **이름은 저장하지 않습니다** — 반 명단과 대조해 학생 ID로 바꾼 뒤 버립니다.
  전송은 동의로 처리하되, 보관은 최소화합니다
- `mask_header.py`는 **남겨 둡니다.** 동의를 못 받는 반이나 외부 시연처럼
  가려야 할 상황이 생기면 `--mask-name`으로 켭니다. 기본은 꺼져 있습니다

## 12.11 배관 검증 (2026-08-07)

실제 답안지 전에 **도구가 제대로 도는지** 합성 답안지로 먼저 확인했습니다.
실제 사진에서 문제가 나왔을 때 도구 탓인지 인식 탓인지 가리려면 이 단계가 필요합니다.

**합성 답안지**: A4 1700×2400, 50문항. 1~25 영어→한글, 26~50 한글→영어,
31번부터 첫 글자 인쇄, 무응답 3개(16·39·46). 인쇄 활자이므로 **손글씨 인식률은
측정 대상이 아닙니다.** 재는 것은 구조를 지키는가입니다.

| 항목 | 결과 |
|---|---|
| 문항 개수 | 50/50 |
| 제시어 (밀림 지표) | **50/50** |
| 첫 글자 분리 | **50/50** |
| 무응답 판정 | 16·39·46 — **정확히 일치** |
| 밀림 경보 | **0** |
| 머리말 판독 | 시험명·선생님·이름·커트라인·문항 수 전부 |
| 장당 시간 | 34~37초 |

**답 불일치 2건은 합성 생성기의 버그였습니다.** 첫 글자와 답을 이어 그리는 코드가
`c` + `ropessional` = `cropessional`을 그렸고, 모델은 **종이에 실제로 그려진 것을
그대로 읽었습니다.** 모델이 맞고 픽스처가 틀렸습니다.

그리고 이게 중요합니다 — 모델은 `cropessional`·`pabortary`처럼 **존재하지 않는
단어를 실재 단어로 고치지 않았습니다.** 우리가 가장 걱정한 "고쳐 읽기"입니다.
다만 **인쇄 활자 한 건이므로 증거로는 약합니다.** 고쳐 읽고 싶은 유혹은 애매한
손글씨에서 훨씬 강해집니다. 실물로 다시 재야 합니다.

### 채점 마크 판독이 가장 걱정한 곳이었는데, 통과했습니다

합성 '채점 후' 사진에 **50문항 전부에 빨간 동그라미**를 치고 **오답 3개에만 사선**을
그어 [12.5](#125-채점-마크-판독--확인-표시와-오답-표시를-구분해야-합니다)의 함정을
그대로 재현했습니다. 결과:

> 채점함 표시: 모든 문항 번호에 빨간 동그라미
> 오답 표시: 번호를 가로지르는 긴 빨간 사선
> 근거: 번호 동그라미는 50문항 전부에 있어 채점 표시이고, 긴 사선은 16·39·46
> 세 문항에만 있어 오답 표시로 판단됨.
> **읽어낸 오답: 16, 39, 46** ← 정확히 일치

동그라미를 오답으로 읽었다면 결과가 통째로 뒤집혔을 것입니다.
**소수에만 붙은 표시를 오답으로 본다**는 규칙이 작동했습니다.

### 사고 과정(thinking)은 이 작업에서 공짜였습니다

켜고 끈 두 번 모두 출력이 **3,306토큰으로 동일**했습니다. adaptive thinking이
전사 작업에서는 사고를 거의 쓰지 않기로 판단한 것입니다.
(별도 실험에서 사고 토큰이 출력으로 과금되는 것은 확인했습니다 — 204 vs 62토큰.)

→ **전사 단계는 사고를 켜 두어도 비용이 늘지 않습니다.** 끌 이유가 없습니다.

## 12.10 이 전환이 바꾸지 않는 것

- **틀린 자동채점보다 느린 채점이 낫다** — 확신도 낮으면 교사에게 넘깁니다. 그대로입니다
- **채점 규칙은 선생님이 정합니다** — AI가 관대해지는 걸 막는 장치. 오히려 더 중요해집니다
- **검수 화면** — 필요합니다. 다만 하이라이트할 좌표를 AI가 같이 내놓게 합니다
- **개인정보** — 답안지 사진은 커밋하지 않습니다
