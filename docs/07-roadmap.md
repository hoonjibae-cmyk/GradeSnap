## Phase 0 (개정) — 페이지 단위 채점 검증

**재는 것은 하나입니다: 답안지 사진 한 장을 통째로 넣었을 때 선생님 채점과 몇 % 일치하는가.**
상세 절차와 지표는 [12 §12.8](12-page-level-grading.md#128-새-벤치마크--새-샘플이-필요-없습니다).

| # | 할 일 | 상태 |
|---|---|---|
| 0.1 | 채점 마크 규칙 확인 (확인 표시 vs 오답 표시) | ✅ 선생님 4명 ([12 §12.5](12-page-level-grading.md)) |
| 0.2 | 채점 전/후 사진 쌍 확보 | ✅ 7쌍 · 212문항 |
| 0.3 | 전사·마크판독·대조 실행 | ✅ 일치율 95.3% → 수정 후 97%대 ([12 §12.12](12-page-level-grading.md)) |
| 0.4 | 해상도 실측 | ✅ 통짜로 충분. `--split` 불필요 |
| 0.5 | 밀림 검증 | ✅ **7장에서 실제 밀림 0건** |
| 0.6 | 비결정성 측정 | ✅ 50칸 중 1칸. 그 칸은 확신도 0.75로 이미 낮았음 |
| **0.7** | **고쳐 읽기 대책** — 읽히는 방식으로 막히는가 | 🔴 **막고 있는 것** ([12 §12.13](12-page-level-grading.md)) |
| 0.8 | 표본 확대 — 놓친 오답 1% 판정에 212문항은 부족 | ⏳ 수집 필요 |

**착수 기준(개정)**: 선생님 채점 일치율 **95% 이상** · 놓친 오답 **1% 미만** · 밀림 경보 **0장**

> 🔴 **0.7이 나머지를 막고 있습니다.** 전사가 `expectution`을 `expectation`으로
> 고쳐 읽고, **확신도가 0.93으로 높습니다.** 확신도 라우팅으로 못 거르므로
> 오채점이 조용히 확정됩니다. 이 대책이 정해지기 전에는 Phase 1 설계를 확정할 수 없습니다.
> 0.8은 사람이 답안지를 모아야 하므로 **0.7과 병행해서 지금 시작**하십시오.

**코드를 쓰기 전에 반드시 해야 합니다.**

### 0.0 ✅ 기존 시험지 생성 시스템 확인 — **완료**

유니크보카는 [`Yunique-Voca-Test`](https://github.com/hoonjibae-cmyk/Yunique-Voca-Test)
저장소로 확인되었습니다. 전체 분석은 [09. 생성기 연동 설계](09-yunique-voca-integration.md).

결론 요약:
- 단어 데이터 5,741행(챕터 1~48) 보유 → **정답표 재입력 불필요**
- 답안 영역이 이미 DOM에 존재(`.answer-line--ghost`) → **좌표 자동 추출 가능, 검출 불필요**
- 🔴 **출제 이력이 저장되지 않음** — 매번 무작위 셔플, 저장 없음.
  인쇄된 시험지의 몇 번이 어떤 단어였는지 알 방법이 현재 없습니다. **연동 전 반드시 수정.**
- 필요한 변경은 약 100줄 (좌표 추출 + examSpec 저장 + QR·마커 인쇄)

**등록 경로는 두 가지를 모두 유지합니다.** 유니크보카 외 시험지는 템플릿 없이
그때그때 만들어지는 경우가 많으므로 **템플릿 편집기는 계속 필요합니다.**
다만 문항 수가 가장 많은 시험지(90~160문항)가 생성기 연동으로 빠지므로
편집기는 10~50문항 규모만 감당하면 됩니다.

### 0.0b 시험지 3분류 확인 — **완료**

시험지가 만들어지는 방식이 세 가지이고 **등록·운영 비용이 각각 다릅니다.**
상세는 [04 §2.5](04-data-model.md#25-시험지-3분류--등록운영-비용이-다릅니다).

| 분류 | 예시 | 매회 작업 |
|---|---|---|
| ① 생성기 출력 | 유니크보카 | 없음 (examSpec 자동) |
| ② 고정 세트 | 문법 백지 TEST | 없음 (유닛당 1회 등록) |
| ③ **매회 신규** | 영작클리닉, Day08-10 단어시험 | **매회 전체 등록** |

**②는 도입 난이도 대비 가치가 가장 높습니다.** 세트가 완성되어 있고 내용·정답이
바뀌지 않으므로 한 번 등록하면 운영 비용이 0입니다.
채점 난이도는 D유형(어려움)이지만 **등록 비용이 일회성**이라 부담이 다릅니다.

**③이 시스템의 생사를 가릅니다.** 선생님이 매회 시험지를 새로 만들고,
공유되는 것은 상단 헤더 표뿐입니다. **본문에 양식이 없어 좌표를 재사용할 수 없습니다.**
등록 시간이 채점 절감 시간보다 길면 도입할 이유가 사라집니다.

### 0.0c ③의 등록 비용 — 두 문제로 분리

정답지는 있지만 **시험지 레이아웃과 무관한 번호별 나열 형태**입니다.
따라서 정답지에서 좌표는 못 얻고, **정답 텍스트만 얻습니다.**
등록을 두 문제로 쪼개면 각각 쉬워집니다.
상세는 [04 §2.5](04-data-model.md#25-시험지-3분류--등록운영-비용이-다릅니다).

| 문제 | 해법 | 예상 소요 |
|---|---|---|
| 정답 입력 | 정답지 **붙여넣기** → 번호별 파싱 | 10초 |
| 좌표 지정 | **문항 번호 OCR**(인쇄 활자라 정확) + 답안 영역 검출 | 30초 + 보정 |
| 검증 | 정답 개수 ↔ 검출 문항 수 대조, **어긋난 것만** 수동 지정 | 가변 |

문항 번호가 인쇄 활자라는 점이 열쇠입니다. 좌표 순서로 문항을 추측하지 않고
**인쇄된 번호를 읽어 매칭**하므로 2단·4단 레이아웃에서도 순서가 꼬이지 않습니다.

**필요한 것**: 정답지 샘플 1~2개 (형식에 맞춰 파서를 만들기 위함)

### 0.0d 헤더 템플릿에 마커·QR 추가 ← **투자 대비 효과 최대**

본문 좌표는 재사용 못 해도, **공통 헤더는 재사용됩니다.**
헤더 파일 하나에 기준 마커 4개와 QR 자리를 넣으면
**그 헤더를 쓰는 모든 시험지가 자동으로 정합 가능**해집니다.
선생님은 평소처럼 헤더를 복사해 쓰기만 하면 되고 바꿀 것이 없습니다.

→ Phase 0에서 헤더 파일을 확보해 마커·QR을 넣은 버전을 만들어둡니다.

### 0.1 채점 표기 규칙 확인
1차 샘플에서 선생님마다 채점 표기가 달랐습니다. 동그라미가 정답 표시인지 오답 표시인지
선생님별로 확인해 문서화합니다.
**이걸 잘못 알면 벤치마크 결과 전체가 뒤집힙니다.**

### 0.1 샘플 수집
- **워드마스터 단어시험 답안지 30장 이상** (1순위 대상, 아래 0.6 참조)
- **채점하기 전 상태**로 촬영 (빨간펜이 답안을 덮으면 인식 방해)
- **책상에 평평하게 놓고** 촬영 (손에 들면 종이가 휨)
- 잘 쓴 것뿐 아니라 **악필(전체의 20% 이상), 지운 자국, 칸을 벗어난 것, 무응답** 포함
- 휴대폰 촬영본 (스캐너 아님 — 실제 사용 환경과 같아야 함)
- 정답표 및 선생님 채점 결과 (= 정답 라벨)

> 이 단계가 프로젝트에서 가장 자주 미뤄지고, 미루면 가장 크게 손해 보는 부분입니다.
> 다음 시험 때 답안지를 버리지 말고 모아두는 것부터 시작하십시오.

### 0.2 인식 벤치마크
동일한 crop 세트에 대해 후보 기술들을 나란히 측정합니다.

> 🛠 **도구 준비 완료** — 실행 절차는 [11. 인식 벤치마크 실행 절차](11-recognition-benchmark.md).
> `make_crops.py` → `fill_truth.py` → `bench_ocr.py`. 남은 것은 정답 라벨입니다.

| 대상 | 비교 후보 | 우선순위 |
|---|---|---|
| **영어 손글씨 단어 (첫 글자 인쇄)** | VLM(prefix 제공) vs VLM(미제공) vs 상용 OCR | **1** |
| 한국어 손글씨 단어 | 상용 OCR(국내/해외) vs VLM(정답 후보 제공) vs VLM(미제공) | 2 |
| 영어 손글씨 문장 | VLM 단독 | 3 |

측정 항목: 정확도 / 판독불가율 / **오인식률(치명적)** / 응답시간 / 건당 비용

**필체 등급별로 나눠 집계합니다.** 전체 평균은 의미가 없습니다.
(양호 / 보통 / 악필 — 사람이 먼저 3등급으로 분류한 뒤 측정)

### 0.3 정합 실험
기준 마커를 인쇄해 다양한 각도·조명에서 촬영, homography 오차를 mm 단위로 측정.
**crop 위치 오차 2mm 이내**가 목표입니다.
샘플에서 확인된 두 조건을 반드시 포함합니다:
- **90도 회전 촬영** — 좌상단 비대칭 마커로 방향이 판별되는지
- **손에 들고 찍어 휜 상태** — 휨 감지가 작동하는지, 어느 정도 휨까지 허용 가능한지

### 0.4 관대함 테스트
일부러 틀리게 쓴 답안 20건을 만들어 AI가 정답으로 판정하는지 확인.
정답 후보를 알려주는 방식의 최대 리스크가 여기 있습니다.
철자 1글자 오류(`hesitage` vs `heritage` 같은 실제 오답 유형)를 반드시 포함합니다.

### 0.5 마킹 판독 실험 *(연기)*
`유/반` 선택형은 이번 샘플에 없었습니다. 해당 시험지가 확보되는 시점으로 미룹니다.

### 0.6 대상 시험지 확정
샘플 분석 결과 **워드마스터 단어시험 26~50번(한글 뜻 → 영단어)** 이
가장 자동채점하기 쉬운 문항군으로 판단됩니다.
영어 손글씨 + 정답 1개 + 첫 글자 인쇄 확정.
벤치마크 결과로 이 판단을 확인합니다.

### Phase 0 산출물
- 기술 선택 확정 문서 (어떤 인식기를 어디에 쓸지)
- 임계값 초기값 + 필체 등급별 예상 검수율
- **판단 기준**: 영단어 인식 정확도 95% 이상 & 오인식률 1% 미만 → Phase 1 착수
- **필요하면 이 시점에 중단하거나 방향을 바꿉니다.**

## Phase 1 — MVP (단어시험)

### 대상 (2차 샘플 분석 후 수정됨)
```
1순위  4지선다 어휘 시험 (어휘끝 수능)     마킹 판독만, 손글씨 인식 불필요
2순위  표/셀형 단어시험 (능률 VOCA 등)      셀이 필기 위치를 물리적으로 강제
3순위  단어시험 한→영 문항                 영어 손글씨, 정답 1개
4순위  단어시험 영→한 문항                 한글 손글씨, 인정 답안 다중
5순위  밑줄형 단어시험                     bbox를 문항 행 전체로
```
§0.0의 생성 시스템 접근이 가능하면 이 순서는 다시 조정됩니다.

**한 시험지의 일부 문항군만 자동채점하고 나머지는 검수로 넘기는 것**이
처음부터 가능해야 합니다. "50문항 중 25문항이 자동으로 끝난다"만으로도
선생님 입장에서는 충분한 이득이며, 이것이 현실적인 도입 경로입니다.

### 범위

> ⚠️ 아래 범위 중 **템플릿 등록·마커 인쇄·정합·crop 관련 항목은 무효**입니다.
> [12](12-page-level-grading.md)로 대체되었습니다. 나머지(로그인, 반·학생 관리,
> 정답표, 촬영·업로드, 확신도 라우팅, 검수 화면, 결과·지표)는 그대로 유효합니다.

```
✅ 교사 로그인, 반·학생 관리
✅ 템플릿 등록 — **두 경로 병행**
   · 경로 A: 생성기 연동 (유니크보카) — examSpec JSON 수신, 좌표 자동
   · 경로 B: 템플릿 편집기 — PDF 업로드, 영역 드래그, 격자 복제, 자동 검출 보조
   · A가 문항 수 많은 시험지를 흡수하므로 B는 10~50문항 규모를 목표로
✅ **③ 매회 신규 등록을 5분 이내로** ← Phase 1의 성패 지점
   · 정답지 붙여넣기 파서 (관대한 형식 허용, 표 미리보기)
   · 문항 번호 OCR + 답안 영역 자동 검출 (밑줄/셀/원문자)
   · 개수 대조 후 **어긋난 문항만** 수동 보정하는 화면
   · 등록 소요 시간을 실측·기록해 지표로 관리
✅ 정답표 (인정 답안 다중, 문항별 출제 방향)
✅ 인쇄용 PDF 생성 (비대칭 마커 + QR 삽입)
✅ 모바일 촬영·업로드 + 즉시 품질 검사 (회전·휨·흐림·마커)
✅ 전처리 → 대비 강화(연필 대응) → 회전 판별 → 정합 → crop
✅ MarkGrader (4지선다) ← 1순위로 복귀
✅ DictGrader (prefix, 무응답 자동 오답 처리 포함)
✅ 확신도 라우팅
✅ 검수 화면 (키보드 조작, 세로 모드, 전 문항 검수 모드)
✅ 결과: 점수 / 오답 번호 / PASS·FAIL / 재시험 명단
✅ 정확도 지표 대시보드 (필체 등급별 분리 집계)
```

### 범위 밖
```
❌ 문장·서술형 채점
❌ 학생·학부모 열람
❌ 재시험지 자동 생성
❌ 통계 분석
```

### 작업 순서
1. DB 스키마 + 인증 + 반/학생 관리 *(1주)*
2. **템플릿 편집기** *(1.5주)* — 가장 오래 걸리고 가장 중요합니다
   50문항 2단 격자를 몇 번의 클릭으로 만들 수 있어야 합니다
3. 인쇄용 PDF 생성 *(0.5주)*
4. 워커: 전처리·회전판별·정합·crop *(1주)*
5. DictGrader *(1주)*
6. 촬영·업로드 UI + 품질 검사 *(0.5주)*
7. 검수 화면 *(1주)*
8. 결과 화면 + 지표 *(0.5주)*

### 현장 투입
- 처음 2주는 **수기 채점과 병행**합니다. 자동 결과를 참고만 하고 신뢰하지 않습니다.
- 매주 무작위 20장 전수 대조 감사
- 오채점률 0.5% 미만이 2주 연속 유지되면 병행을 중단합니다

### 완료 조건
- 단어 시험 30장 채점이 수기 대비 **절반 이하 시간**
- 자동 확정 오채점률 **< 0.5%**
- 선생님이 다음 시험에도 **자발적으로 사용**

## 확정이 필요한 사항

기획 단계에서 아직 정해지지 않은 것들입니다.

1. **호스팅** — 학원 내부 서버 / 클라우드 / 관리형(Supabase+Vercel) 중 선택
2. **개발 인력** — 1인 개발인지, 외주인지에 따라 일정이 2배까지 달라집니다
3. **1차 대상 선생님** — 전체 도입이 아니라 **1~2명으로 시작**해야 합니다
4. **답안 이미지 보관 기간** — 학원 개인정보 처리방침과 정합 필요
5. **AI API 예산 상한** — Phase 0 실측 후 결정
